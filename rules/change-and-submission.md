# 变更、交付与提交规范

> 上游（我引用）：[AGENTS.md](../AGENTS.md) §4、§8.4、§9。
> 下游（引用我）：[AGENTS.md](../AGENTS.md) §6.1。

## 1. 执行前

- 读取本文件、当前进度和任务依据，确认授权范围及完成标准。
- 正式需求、契约和规则先讨论再写；对已确认内容的整理落盘及用户明确要求的补齐可直接执行，不重复索取同一授权。
- 查看目标文件当前内容，保留他人修改；未建立 Git 仓库时不假称已有版本记录，不自行初始化。
- 发现范围外问题先记录，不夹带修改；依赖、技术栈和公共契约变更按权限要求处理。

## 2. 交付前检查

| 检查项 | 通过标准 |
| --- | --- |
| 范围 | 所有变更属于批准任务，无无关变更 |
| 依据 | 实现能回查需求/任务；尚未建立编号时明确记录决定来源 |
| 一致性 | 代码、提示词、配置、契约和规则不冲突 |
| 验证 | 适用检查已执行；失败、阻塞和未覆盖范围明确报告 |
| 引用 | 实际链接有效，结构性依赖双向更新，索引同步 |
| 记录 | 日志、进度及适用计划/缺陷状态已更新 |
| 内容 | 不含秘密、无关素材、意外生成物或他人无关改动 |

功能未实现、只有模拟验证或存在未满足验收的失败时，不宣称功能完成。文档交付只说明文档完成，不宣称运行控制已经生效。

## 3. Git 与部署边界

- 本地编辑、Git 提交、推送、合并、部署和平台发布分别授权、分别报告。
- 未获授权不提交、推送、合并或部署；准备完成不等于动作已经执行。
- 获准提交后检查实际差异，只纳入本任务文件，使用概括具体变更的提交说明；不绕过检查，不覆盖他人工作。
- 部署和回滚在对应阶段确认环境、配置、验证与恢复步骤，本文件不预先授权生产操作。

## 4. 完成汇报

```text
完成内容：

剩余问题与限制：
提交、推送或部署状态：
```

报告与实际文件、工具输出和记录一致；不得把工具的文字自述单独作为完成证据。
