## 1. 开发记录的位置

| 位置 | 职责 |
| --- | --- |
| docs/00-process/00-02-progress/progress.md | 唯一当前进度快照：阶段、任务、阻塞、待确认和下一步 |
| docs/00-process/00-01-logs/YYYYMMDD.md | 每日工作历史，使用用户时区 Asia/Shanghai；同日分任务追加，不覆盖旧记录 |
| docs/07-delivery-plans/ | 计划建立后维护任务依赖、标准和状态；未建立不编造任务编号 |
| docs/08-test-reports/ | 实际测试执行、证据与缺陷；有测试活动时再创建对应报告 |

现有项目 work/ 学习记录继续保留，不迁移或删除，不写入全局记忆。每轮知识摘要追加到工作区根目录 work/会话总结/YYYYMMDD.md，新主题和重要修订同步 work/知识索引.md；具体流程遵守 source-check-workflow.md。正式工程状态以上述进度快照为准，知识摘要不复制完整执行日志。

## 2. 更新时机与状态

- 每轮收口、任务完成/失败/阻塞、需求或决定变化、验证结束时，同次更新适用记录。
- 任务状态：待开始、进行中、待确认、阻塞、已完成。任务文件创建不代表任务完成。
- 已完成须满足实际范围与验证要求；记录完成不等于功能实现或上线。
- 有计划时同步主计划、看板和子计划；缺失文件标记待建立，不为凑记录创建虚假依赖。
- 已确认决定和新假设分别记录；变更已确认决定时说明变更依据。

## 3. 每条日志至少包含

```text
任务及依据：
实际操作与变更文件：
验证方式、实际结果与证据：
已确认决定：
未完成事项或阻塞：
下一步：
提交或部署状态：
```

验证尚未执行写“待验证”；模拟验证明确标注。出现失败保留事实及修正结果，不将第一次失败改写为从未发生。

前期原型/契约静态检查属于辅助记录，放工作区work的对应任务目录；只有正式需求用例的实际执行证据进入docs/08-test-reports，不与原型本体混放。

## 4. 运行日志与开发日志分开

- 本文件先规定开发记录。系统运行日志的存储、字段和保留时间在数据与主子 PRD 阶段确定，不假称已有日志服务。
- 运行记录需支持回查输入及修订、规则/模型/提示词版本、工具动作、候选产物、人工决策、状态、失败、重试和成本；未知数据标记未知，不估造。
- 输入记录优先保存必要标识与受控引用；是否保存完整文本、音视频另按授权确定，不把全量素材无差别写入日志。
- 不记录密钥、认证令牌或无关个人信息；错误消息需要脱敏。不得为记录日志额外调用外部服务。
- 记录可核验的动作和产物，不要求读取或保存模型内部思考过程。
