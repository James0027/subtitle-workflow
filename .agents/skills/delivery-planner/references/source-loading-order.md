# 字幕项目开发计划的资料读取顺序

当前是主PRD阶段，准备好技能不代表现在写开发计划。只在明确的代码实施计划任务中使用。

## 先清单，再细读

| 顺序 | 实际位置 | 使用及缺失处理 |
| --- | --- | --- |
| 1 | `AGENTS.md`、`rules/`、`docs/00-process/00-02-progress/progress.md` | 确认阶段、授权、当前规则；不假设未建立的coding-standards存在 |
| 2 | `docs/05-prd/mainprd.md` | 全局状态、权限、功能边界和REQ-MAIN/AC-MAIN验收；当前是待评审草稿 |
| 3 | `docs/05-prd/`对应模块子PRD | 按任务选读契约/接口/验收；未建立的相关任务缺前置，不猜细节 |
| 4 | `docs/03-foundation/schema.md`、rule-registry/metrics/metric-events/samples | 字段、规则、指标与样本的权威；逻辑定义不等于生产表/接口已实现 |
| 5 | 已确认技术方案与内外部接口契约 | 以实际建立位置为准；接口类任务缺契约不能写成可开发 |
| 6 | 现有主计划/看板/当前子计划（如有） | 更新前须读三者；尚无计划不创建占位来凑清单 |
| 7 | `code/`、`config/`、`tests/`、`evals/`及实际测试资产 | 确认现状和可执行验证；零字节文件不是完成证据 |

按项目source-check核对参考同类产物、课件、meeting、work已确认记录。新增计划用完整清单；更新只补受影响部分，保留原计划/看板/子计划关联。大文件按主题与章节读，不一次加载全部子PRD。

## 本项目路径差异

- BRD为`docs/01-brd/BRD.md`，主PRD为`docs/05-prd/mainprd.md`，不带项目后缀。
- 数据定义平铺`docs/03-foundation/`，没有参考工程的03-01—04子目录；不因此重复建术语/API/schema文档。
- 尚无具体存储与接口。相关子PRD/技术方案确定后引用其实际章节；需要时才建立正式契约，不在技能迁移中虚构。
- 正式开发计划进入`docs/07-delivery-plans/`，进度只存摘要；技能复制/验证夹具在work，不冒充计划交付。
