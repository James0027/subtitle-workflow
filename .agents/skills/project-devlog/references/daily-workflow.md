# 本项目日志工作流

依据项目`rules/progress-and-logs.md`，不是新的日志规则源。

1. 确认本轮是否形成实质产物、重要决定、阶段变化或收口；纯读取/短答无需机械追加。需保留的决定按source-check记录。
2. 用用户时区Asia/Shanghai确定YYYYMMDD，读取唯一进度和当日日志。无当日日志时参考`../assets/daily.md`创建；已有文件保留格式，追加本轮主题，不强制补六章或无意义复盘。
3. 写清任务与依据、实际变更、验证及证据、已确认/待定、下一步、提交/部署状态。不凭原型、占位文件、脚本语法通过宣称业务完成。
4. 有正式计划才同步其对应任务；当前主PRD阶段不生成开发计划、测试执行或上线记录。最新进度与日志应一致，历史记录保留。
5. 工作区外层work存在时追加会话摘要；新增知识入口/决定替代旧稿时更新知识索引。未有外层来源时说明缺失，不伪造。
6. 收口时可按需要读取实际git diff/status，提交记录仅在需要时读取；使用明确Asia/Shanghai日期范围，不把宿主的today当用户日期。当前未提交就如实记录。
7. 不写全局记忆，不因总结自动修改权限/业务规则或发送材料。
