# 字幕项目测试用例编写（准备完成，按阶段使用）

先读[AGENTS](../../../AGENTS.md)、[测试规范](../../../rules/testing.md)及[来源核对规则](../../../rules/source-check-workflow.md)。PRD定义预期，代码仅辅助定位实际数据链路，不能拿现有实现替代需求。技能迁移不触发生成/执行测试，也不改变主PRD待评审状态。

## 来源与映射

- 主PRD：`docs/05-prd/mainprd.md`；原始验收覆盖台账：`docs/05-prd/acceptance-map.md`；当前REQ-MAIN-R01—R19分别有AC-MAIN-Rxx-N/E/A三类验收场景，共57项，未执行。
- 相关子PRD按模块读取，尚未建立或预期不唯一时列待确认，不补造工具、接口或数据库。
- 字段、规则、指标、样本从`docs/03-foundation/`对应现有文件读取，不建参考工程的glossary/API空目录。
- 正式TC用独立稳定ID回链REQ/AC及PRD章节；不能仅把57项场景复制一遍称正式用例完成。每条P0/P1须至少正常、异常和权限用例，子PRD新增需求同样覆盖。

## 按需读取完整依赖

- [方法论/BCDE](references/methodology.md)：设计边界、条件、数据、异常。
- [共享模板](references/templates-shared.md)：主索引、覆盖矩阵和文件头。
- [资产命名](references/project-conventions.md)：按模块/业务职责组织，稳定编号，不按电商域照搬。
- [模块用例](references/type-domain.md)、[回归](references/type-regression.md)：分别在对应用例设计时读。
- [自检](references/self-check.md)：单条/文件/体系覆盖。

## 产物和流程

1. 读取任务相关PRD及验收点，列出需求/场景/预期/待定及可观察证据。语义质量用授权样本与独立参考，不能靠格式PASS或模型自评证明。
2. 展示本次用例范围与文件安排；若用户已明确批准相同范围，直接按授权执行，不重复要确认。未授权的范围变化再澄清。
3. 在`docs/06-testcase/tc-main-subtitle-workflow.md`建立或更新索引；按实际模块/共享职责生成域文件，各TC包含前置、输入、步骤、预期、证据、清理与PRD回链。
4. 测试数据按实际技术方案选择JSON/文件夹具、模拟响应或SQL。当前存储未定，不生成生产DDL、MySQL专用SQL、数据库连接配置或空sql目录；用例可先描述数据要求并标待实施。
5. SQL只在已批准存储与真实schema明确时按需生成，每条准备/清理有边界；不能直接对真实素材或人工稿执行破坏性重置。使用合成/脱敏数据并标明，模型/平台测试所需授权不能由本技能代授。
6. 更新覆盖矩阵与待确认项，自检PRD依据/输入/可观察预期/权限/清理和引用完整性；生成用例不算执行或测试通过。

## 编号与写入边界

沿用已有TC前缀；尚无时按references规划稳定前缀。01—09/11—19只作为API/UI分组示例，不限制每类最多9条；超出使用稳定连续编号并独立列类型，不重排历史编号。P0/P1需求优先级与文化风险等级分开。

只写测试资产及索引，不修改PRD、schema、规则、业务实现或执行计划。预期冲突时在用例中记待确认，按来源流程反馈；不生成“已核查通过”或真实执行报告。报告执行阶段另用经本项目实际环境适配的执行方式，未迁移的参考test-case-runner不视为可用工具。
