## 1. 原型解释什么

点击动作 → 读取哪些信息 → 谁/代码/模型分别做什么 → 校验与分支 → 记录前后变化 → 用户响应 → 交付给谁。

参考工程的实际页面同时包含用户操作和后台可观测记录；本轮按用户要求，着重展示后台应发生的处理及效果，不再扩展字幕编辑器。按钮仅用于浏览说明。

接受、批量接受、逐条驳回、升级和回滚是人工审核动作，不是新增业务阶段。六处理模块也不改写原文七阶段。

## 3. 入库的关键区别

- **素材登记**：文件收到并列清单，不自动选定母版，不自动进入ASR。
- **母版确认**：选定权威视频修订与可用声音，记录附件关系；母版不是UI模板。课件 §5.4示例有media_id及换母版新建要求，生成算法、确认SOP后定。
- **任务单**：表单结构可复用；用途、范围、语言/市场/受众、输出和责任由人确认，代码检查缺项。原文没有给出完整任务单schema，这里是设计建议。
- **阶段开工**：区分业务条件与真实执行条件。完整多语目标缺失时，不宣称整个任务就绪；若单独先做源语处理，需明确任务范围与授权。源语专用任务显式标注目标条件不适用。
- 缺独立音轨可评估视频内声音；没有脚本或已有字幕不一律阻断。声音不可用、附件错配和缺业务定义分别处理。

## 4. 三哲学及后续锁定线索

| 项 | 当前展示 | 后续工程阶段 |
| --- | --- | --- |
| 关键规则 | 缺项阻断、确认稿保护、规则版本、发布闸门与停止说明 | 规则锁定、状态机、服务端权限与程序校验 |
| 过程驱动 | 输入、处理、分支、前后版本、输出与接手职责 | 数据锁定时定义manifest、步骤结果及产物血缘 |
| 双向引用 | BRD功能→本动作→规则/契约→实现→测试→事件；未建立项明示 | 主子PRD及开发测试补齐真实引用 |
| 数据 | 素材、母版、任务单、候选/确认稿、运行、人工决定、检查与文件 | 第④步确认字段、关系、脱敏及样本；本轮不定表结构 |
| 规则 | 条件依任务/阶段适用，不猜优先级或通用阈值 | 第⑤步定适用范围、来源版本、优先级及软硬规则 |

原型不是把第④—⑥步全部先做完再展示；它先暴露需要哪些数据、规则与反馈，便于后续逐项确认，发现冲突可返回修改原型。
