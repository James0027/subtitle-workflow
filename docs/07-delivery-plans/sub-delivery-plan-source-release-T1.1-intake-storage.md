### 1. 本步骤的边界

创建真实Task草稿 → 登记原件/附件 → 工程探测 → 选择主声音并准备派生 → 核对配套与缺项 → 人工确认母版/任务 → 交T1.2检查执行准入、T2.1处理音频。

本步骤不生成正式台词、不做角色推断、不调用Gemini进行完整分析。可选的AI错配辅助须另确认用途；模型不能代签母版。缺字幕/脚本不强制变成不合格素材。

### 2. 素材情况及处理

复用samples.md的PKG-01—06；下表补入本步骤的实现要求。

| 情况 | 工程处理 | 人工/交接要求 |
| --- | --- | --- |
| 视频＋独立音频＋字幕/脚本 | 分别探测、登记来源/版本/覆盖与关联，不因资料齐全自动通过 | 指定主视频/音轨/资料；路线由Task明确 |
| 有声视频，无独立音频 | 用FFmpeg显式选轨，另存派生音频，复核可解码性/覆盖与时间映射 | 不要求重复上传；派生不冒充独立原配音轨 |
| 视频＋独立音频 | 核对起止、时长、覆盖及版本；有可比声音时提出内容/偏移线索 | 时长相等不证明配套；不确定则回听确认，不自动替换视频内音轨 |
| 视频多条音轨 | 列出轨道、语言标签、声道、时长等；标签只作线索 | 由任务/人明确主轨；无法确定不默认第一轨 |
| 视频无声，有独立音频 | 保留视频基准，检查独立音频覆盖/来源及可用配套证据 | 不能做波形比对时说明未覆盖，由人核配套 |
| 无可用声音、损坏或空音轨 | 登记真实失败，阻断依赖声音的处理 | 提示补料，不以画面/脚本补造台词 |
| 缺脚本、角色/术语资料 | 登记缺项及影响；保持相关来源为空 | 可继续转写，角色/专名待核对；脚本不等于角色表/术语表 |
| 缺字幕 | 准备transcribe路线输入 | 不虚构原字幕；已有稿核对/对齐需另有选定字幕 |
| 错集、错剪辑、错轨、缺段 | 标记对应文件/区间及证据；不能确认配套 | 换料或人工解除疑点后重检，不靠拉长/剪短掩盖问题 |

只有音频的文件可登记；能否在无视频条件下完成当前任务仍按01子PRD和Task类型判断，不扩大本批母版范围。

### 3. 技术选择与“对齐”分工

首版实现建议：本地ffprobe/FFmpeg完成技术准备；素材核验阶段暂不调用AI。内容配套通过可播放证据和人工确认完成，波形匹配/AI语义错配检测留扩展，不列为本步骤已承诺自动能力。T2.1仍直接使用音频大模型；这不恢复Whisper。

主声音选择：仅一条内嵌音轨且无独立音频时可预选该轨并准备，确认单仍显示来源；多轨或同时有独立音频时由人明确选择，选择前不生成最终派生音轨。轨道语言标签不替代用户指定源语言。

技术检查处理范围与确认范围一致，实际解码校验不得只探测文件头。使用可配置超时、资源/大小限制和单worker；超时/达到限制必须失败或待处理，不能报已检查。首批本地素材准备建议媒体单文件500MiB、处理范围10分钟，作为待确认试点上限，不是Gemini能力或性能保证；资料附件上限和具体允许格式在工程交接中核实际解析能力后列白名单。大于上限明确提示缩小范围/补交，不静默截取前10分钟。


- ffprobe：探测文件/轨道、起始时间、时长、采样率/声道、帧率等；另做实际解码检查。元数据不等于内容正确或整片解码成功。
- FFmpeg：按选定轨道抽取/必要格式转换，原件不覆盖；绑定父Asset、ingest Run、参数、选轨和母版offset映射。派生优先使用无损音频并保留采样率/声道，具体封装由engineer核目标API支持后固定；若需转换另存模型输入版本，保留映射，不默认套用旧Whisper参数。
- 默认保留背景声音，不先降噪/分离人声；不把多轨、多声道未加区分地混成一条。衍生转换另留记录。
- 工程核对：可读性、时间范围、来源/版本、轨道关系。存在同源可比声音时可验证波形/特征的偏移线索；算法、窗口、阈值待验证，不把配音/不同混音直接判错。
- 配套疑点：检查多个时间位置；单点匹配不能证明整片同步。恒定偏移、速度漂移、缺段分别反馈，首版建议不自动拉伸/拼补独立音轨，人工确认调整后另存派生与映射。
- AI只辅助具体内容疑点，不证明素材身份。最终母版由有权人回听/音画核对后确认。从视频抽轨证明来源链，不证明原视频口型同步；本步骤也不等于台词时间边界已准确对齐。

官方能力依据：[ffprobe](https://ffmpeg.org/ffprobe.html)、[FFmpeg](https://ffmpeg.org/ffmpeg.html)。这是选型依据，不是本项目已实现证据。

### 4. 操作顺序与素材检查单

不再另做展示文档；本节即页面行为的工程依据，T3.2按本节接入现有01/02页面。

| 步骤 | 用户看到/操作 | 后台实际工作及反馈 |
| --- | --- | --- |
| 1 上传与任务草稿 | 填作品/集数、源语言，上传主视频；可附独立音频、脚本、角色表、术语表或已有字幕 | 创建稳定Task草稿；每文件单独接收/校验/保存原件，失败文件不登记为可用；上传进度不冒充检查进度 |
| 2 自动技术检查 | 看到文件时长、音轨数量、可读性和失败原因 | ffprobe探测并实际解码检查；按文件记录真实等待/检查/失败，不编百分比 |
| 3 选主声音 | 单一内嵌轨可预选；多轨/独立音频显示可试听候选，由人明确选择 | 记录主声音选择，选定后FFmpeg准备派生；无法确定不擅自合并轨道 |
| 4 对照检查 | 看视频与所选音频的起止/时长/覆盖，对照播放开头、中间、结尾并可任意定位 | 共用母版时间轴；视频原声音和候选音频切换试听，避免同时播放干扰；没有可比较声音时明确标未覆盖 |
| 5 查看检查单 | 看到通过、失败、待核对、未检查的具体依据；补料/换轨可回上一步 | 已检查结论保存Asset.inspection/Media.match_checks，缺项附影响；先不写人工配套pass |
| 6 确认与交接 | 有权人确认“选对素材/主声音”和任务范围 | 分别保存母版/Task确认，引用准确修订；仅显示本步骤准备完成，后续模型执行仍由T1.2检查授权 |

检查单内容：确切文件/版本及来源、作品集数、源语言、所选视频/主音轨、时长和任务覆盖、起始偏移信息、派生关系、配套检查方法/证据、缺项及影响、待处理人、当前确认修订。

工程通过不等于内容配套通过。首版不自动给“同一集/正确剪辑”结论；人可回听多点并核对作品资料后确认。开中尾只用于辅助，不能宣传抽看三处证明整片一致。

阻断：主视频/声音不可用、未选主轨、任务区间非法/超限、已发现错配未解除、缺确认权或确认修订过期。缺可选脚本/角色表/术语表不统一阻断；语种模型探测仅留后续步骤，当前源语言由用户提供。

独立音频有偏移/漂移时，首版不提供自动修复或“强制通过”按钮。先改选视频内正确音轨、补交正确版本或明确调整任务区间，再复检；需要人工修正音频属于后续单独确认的能力。

确认后换文件/选轨、改范围或源语言，都必须形成对应新修订并使受影响检查/确认失效；不复用旧勾选。刷新/重启读取已保存结果，不自动重做准备；中断任务明确显示中断，可发起有记录的新attempt。

### 5. 实现拆分与验收

| 顺序 | engineer具体工作 | 验收依据 |
| --- | --- | --- |
| 1 | 任务草稿、受控原件/附件保存、hash及来源记录 | ID稳定、原件不覆盖、防重复/旧版本冲突、重启可读 |
| 2 | ffprobe探测、解码检查、多轨清单、失败记录 | 损坏/空轨/多轨/未知元数据如实显示，不伪造通过 |
| 3 | 选轨和FFmpeg抽轨、派生保存及时间映射 | 无独立音频仍能准备；声音/母版区间一致；原件hash不变 |
| 4 | 配套检查、缺项反馈、检查单与人工确认 | 错集/缺段/不确定不可自动放行；缺脚本不误阻断；确认绑定当前版本 |
| 5 | 接T1.2/T2.1、异常及恢复验证 | 未确认不启动音频理解；失败保留原因/中间产物；同请求不重复抽轨 |

阶段自测覆盖正常、异常、权限三类，先复用TC-SRC-INT及MAIN-R01/R02；多轨、错版、偏移和无声使用获准样本实际验证，不把Mock当真实媒体通过。页面由T3.2配合，但本步骤的核验规格只在这里维护。
