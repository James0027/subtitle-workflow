## 1. 这一版要交出什么

用户确认素材/母版和任务，系统按明确路线生成或检查源字幕候选；用户查看声音/文字/时间并实际确认；系统生成所选源语格式文件，重新解析核对，保留完整版本和步骤记录。

```text
01收料/母版 → 02任务/阶段就绪 → 03源语三路线 → 04人工审阅 → 08源语检查/导出
                 ↕ 共享上下文、权限/版本/预算、Run/attempt/step与事件
```

三路线分别是transcribe、verify_existing、align_existing。采用工具前分别验证能力，不把“ASR返回时间戳”当成“已有文本强制对齐”。工具不支持某语种/输入条件时返回缺项/不支持，不能静默换路线。

首批输出建议从纯文本SRT开始，待D02确认；其他已设计格式保留后续接入。若业务需要VTT/复杂样式/平台验收，须先验证该格式与规范，不能借最小版减少已确认任务的输出要求。首批内部文件可为VALIDATED，但须真人签发后正式导出才达到约定终点，不制造平台回执或发布结果。

## 5. 一次任务怎样真正运行

1. 先创建真实Task草稿并取得稳定ID；接收原件，素材准备/抽轨以绑定草稿的ingest Run记录。人工确认Media后确认Task，原件/派生关系固定，确认不换Task ID。
2. Task保存为不可变定义快照；人工确认当前版本；按route检查声音、字幕、范围及规则，记录就绪/缺项。
3. 身份/动作许可、输入/版本、预算/停止检查通过，创建或复用Run；业务请求先持久化，再返回受理和查询引用。
4. 串行工作者以短事务领取READY运行；媒体/模型在事务外执行。各attempt/step留真实输入输出/时间/失败，结果提交前再次核对权限/版本。
5. 返回候选/疑点，默认人工复核。没有实际校准/自动准入配置时不启预授权自动档；编辑完成提交待审，由有审核权的真人明确接受/确认后形成受保护修订。
6. 读取当前确认稿、生成文件并重新解析，比较文字/时间/顺序/允许变换；内部输出及行映射可追溯；真人再对当前包签发，正式导出请求才开放文件。未审/旧版/检查失败/未签均不得正式导出。
7. 有当前真人签发及实际正式导出/交接记录后，任务按约定源语终点完成；平台发布/真实回执仍是独立后续能力，不自动调用。

进程重启时不得把RUNNING直接当未做而重新收费。保留attempt及外部调用引用，先查实际状态；无法核实时转WAITING_HUMAN并说明运行结局未知。有权人确认恢复后再检查。不会因重启、新Run或新Task版本清空原任务历史费用。
