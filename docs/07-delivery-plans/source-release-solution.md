## 1. 这一版要交出什么

用户确认素材/母版和任务，系统按明确路线生成或检查源字幕候选；用户查看声音/文字/时间并实际确认；系统生成所选源语格式文件，重新解析核对，保留完整版本和步骤记录。

```text
01收料/母版 → 02任务/阶段就绪 → 03源语三路线 → 04人工审阅 → 08源语检查/导出
                 ↕ 共享上下文、权限/版本/预算、Run/attempt/step与事件
```

三路线分别是transcribe、verify_existing、align_existing。采用工具前分别验证能力，不把“ASR返回时间戳”当成“已有文本强制对齐”。工具不支持某语种/输入条件时返回缺项/不支持，不能静默换路线。

首批输出建议从纯文本SRT开始，待D02确认；其他已设计格式保留后续接入。若业务需要VTT/复杂样式/平台验收，须先验证该格式与规范，不能借最小版减少已确认任务的输出要求。首批内部文件可为VALIDATED，但须真人签发后正式导出才达到约定终点，不制造平台回执或发布结果。

## 2. 现有基础与缺口

本轮实际读取62个code/config/tests/evals框架文件，均0字节；code/web无文件，requirements.txt也未形成依赖基线。没有实际后端、数据库、队列或测试实现。

这些事实只说明本次环境检测结果；未验证安装兼容、工具速度、声音质量或模型效果。

## 3. 推荐技术路线及采用边界

| 部分 | 推荐候选 | 原因与使用范围 | 未定/限制 |
| --- | --- | --- | --- |
| 页面 | 原生HTML/CSS/JS，沿V3字段和交互实现 | 先接01/02/03/04/08，减少首批框架依赖 | V3仍保留为原型，产品页面写code/web，不把折叠示例当保存 |
| 应用接口 | Python + FastAPI/uvicorn | 与候选音频工具生态及现有目录容易衔接；提供受控业务接口 | 仅推荐，未安装；具体版本与运行解释器在T0.1冻结 |
| 状态/事件 | SQLite + 版本化JSON载荷；原件/派生文件存受控本地目录 | 单机试点先保持事务、不可变修订和事件；复用标准库存取能力 | 一个API实例、一个串行工作者为首批建议；不是多机/高并发方案 |
| 媒体探测/处理 | ffprobe/FFmpeg薄适配 | 探测、选轨、抽音轨及时间基准；原件不覆盖 | 核实际构建/编解码与许可；不能证明作品/音画语义对应 |
| 新转写 | Python路线优先验证faster-whisper；原生CPU路线可比较whisper.cpp | 择一接入，产候选/实际时间/疑点；保留来源 | 权重/许可证、首批语种、硬件和真实样本待确认，不同时双接凑能力 |
| 已有稿核对 | 解析已有稿 + 声音证据/ASR差异 + 人工回听 | 项目只实现版本化差异定位和语义保护等业务适配 | 字符差异不证明语义正确，无差异也不代替人工确认 |
| 已有稿对齐 | 单独验证WhisperX或同等明确支持已知文本的对齐工具 | 输入文字不改，输出时间候选及未对齐标记 | 模型按语种/窗口验证；无粗时间窗口的整稿对齐暂为能力缺口 |
| 字幕解析生成 | 评估pysubs2用于SRT/有限VTT | 复用解析器，项目补版本/行映射/解析一致性 | 不保证复杂样式、定位、TTML无损；所选格式逐个验证 |

推荐是针对单机首批的工程判断，不是已经采用的栈。[FastAPI支持静态文件服务](https://fastapi.tiangolo.com/tutorial/static-files/)；其[后台任务文档](https://fastapi.tiangolo.com/tutorial/background-tasks/)提醒重计算应单独处理。本方案不靠请求内BackgroundTasks保存长任务，把Run先持久化再交串行工作者。SQLite的[使用范围](https://www.sqlite.org/whentouse.html)和[事务约束](https://www.sqlite.org/lang_transaction.html)要求认真处理单写者、锁与竞争；长推理不能占数据库事务。

音频工具官方仓库：[faster-whisper](https://github.com/SYSTRAN/faster-whisper)、[WhisperX](https://github.com/m-bain/whisperX)、[whisper.cpp](https://github.com/ggml-org/whisper.cpp)、[FFmpeg](https://ffmpeg.org/ffmpeg.html)、[pysubs2格式支持](https://pysubs2.readthedocs.io/en/latest/supported-formats.html)。来源核验日期2026-10-20；详细比较在工作区work/首批落地准备/tool-research.md，均未安装/推理。

## 4. 模块、工具、Prompt与上下文怎样配合

| 环节 | 工程代码/工具 | 模型/Prompt | 人工与结果 |
| --- | --- | --- | --- |
| 收料/确认 | 文件接收、授权/类型/可读性、探测及配套检查记录 | 不默认需要大模型 | 人核对母版；检查PASS不代签 |
| 新转写 | 取正确声音和范围、调用ASR、统一毫秒与offset、检查结构 | ASR模型；是否有初始词表取决于工具，不等同系统Prompt | text/timing候选、疑点；人最终回听 |
| 核对/对齐 | 字幕解析、受控差异、强制对齐及回退检测 | 首批不强制额外LLM改写；必要语义辅助单独评测后接入 | 保留输入文字/原时间，人处理疑点 |
| 审阅/版本 | 草稿与确认、分支并发、受控写入、回滚/影响分析 | 模块只另存候选；无终审/锁定写入权限 | 人明确确认；旧确认稿留历史 |
| 检查/导出 | 确定性校验、生成、重解析、逐cue映射/比较 | 不需要为导出增加模型调用 | 先内部生成/检查，有权真人签发后才拿到正式文件；签发首批必需 |

首批上下文最小集：Task快照、声音/已有稿版本、范围/时间基准、必要术语/角色/脚本引用、有效源语输出规范。没有资料就标缺项；不自动抓取网络、不整片盲塞，也不要求每模块独建知识库。

具体模型、Prompt模板和输入格式在T0.1工具能力验证后写入相应适配器/模块提示词目录。空system.txt不是运行规范；实际不调用语言模型时manifest记not_used，不用假Prompt版本凑记录。若增加语义模型，须补输入裁剪、保护项、注入隔离、版本、失败/评测和费用控制，再授予相应调用权限。

## 5. 一次任务怎样真正运行

1. 先创建真实Task草稿并取得稳定ID；接收原件，素材准备/抽轨以绑定草稿的ingest Run记录。人工确认Media后确认Task，原件/派生关系固定，确认不换Task ID。
2. Task保存为不可变定义快照；人工确认当前版本；按route检查声音、字幕、范围及规则，记录就绪/缺项。
3. 身份/动作许可、输入/版本、预算/停止检查通过，创建或复用Run；业务请求先持久化，再返回受理和查询引用。
4. 串行工作者以短事务领取READY运行；媒体/模型在事务外执行。各attempt/step留真实输入输出/时间/失败，结果提交前再次核对权限/版本。
5. 返回候选/疑点，默认人工复核。没有实际校准/自动准入配置时不启预授权自动档；编辑完成提交待审，由有审核权的真人明确接受/确认后形成受保护修订。
6. 读取当前确认稿、生成文件并重新解析，比较文字/时间/顺序/允许变换；内部输出及行映射可追溯；真人再对当前包签发，正式导出请求才开放文件。未审/旧版/检查失败/未签均不得正式导出。
7. 有当前真人签发及实际正式导出/交接记录后，任务按约定源语终点完成；平台发布/真实回执仍是独立后续能力，不自动调用。

进程重启时不得把RUNNING直接当未做而重新收费。保留attempt及外部调用引用，先查实际状态；无法核实时转WAITING_HUMAN并说明运行结局未知。有权人确认恢复后再检查。不会因重启、新Run或新Task版本清空原任务历史费用。

## 6. 先验证哪些，怎样通过

| 验证层 | 测试依据 | 可证明/不可证明 |
| --- | --- | --- |
| 合成契约/状态测试 | [正式TC](../06-testcase/tc-main-subtitle-workflow.md)、合成数据配方、可控依赖返回 | 权限/版本/状态/失败分支；不能证明真实ASR质量 |
| 工具兼容验证 | 实际解释器、固定版本/权重、首批语种及授权短样本 | 本机工具可运行及输入输出边界；不能借官方性能数据报项目效果 |
| 模型/时间质量评测 | samples协议、独立人工参考、冻结计数与匹配策略 | WER/CER、时间边界及严重错误等实际值；阈值未批准前不判达标 |
| 端到端人工验收 | 真实授权视频/声音、源语任务及输出要求 | 收料→候选→人审→文件/血缘可用；不能冒称平台发布 |

测试设计状态与执行状态分开：正式TC可以先写，当前均NOT_RUN；未有实际实现/样本时不创建“业务测试通过”报告。依赖模拟必须标SIMULATED，正式模型评测必须是真实授权样本。
