## 1. 范围与需求

从明确源版本和目标分支开始，生成、检查并交出初翻候选。本文消费上下文09提供的受控引用，不建设检索平台，不定义通用审阅状态机。首批源语闭环不运行翻译；本稿定义后续接入行为，真实语种、模型与批次待定。

单模块翻译须已有确认任务、合格源稿和明确目标要求；外部源稿先登记核实，不要求重跑本系统ASR。不把缺输入的多语任务自动降成单模块任务。

| 局部需求 | 优先级 | 上游需求 | 本文负责 |
| --- | --- | --- | --- |
| REQ-TR-01 | P0 | REQ-MAIN-R07 | 固定源修订、目标分支与上下文，缺项不猜补 |
| REQ-TR-02 | P0 | REQ-MAIN-R07 | 先取锁词再生成，逐出现位置检查锁词与跨集一致性 |
| REQ-TR-03 | P0 | REQ-MAIN-R07 | 检查关键语义和QE依据，阻断不合格候选 |
| REQ-TR-04 | P1 | REQ-MAIN-R07 | 提供逐句对比、重译和审阅交接，保留原稿 |
| REQ-TR-05 | P0 | REQ-MAIN-R07 | 可追踪、可局部重跑，执行与内容接受分开 |

R07由本文主责；跨项目隔离归09，人工采纳/版本归08，授权/预算/幂等归10。本文不扩大上游业务范围。

## 2. 输入输出与页面数据

统一引用`Ref={entity_type,entity_id,revision}`；有内容版本必须带revision。实际字段及枚举以schema为准，不使用“最新稿”模糊引用。

| 来源/输入 | 本文读取与检查 | 产出/展示 |
| --- | --- | --- |
| Task确切快照 | task_revision、module_plan、range、target_variants、execution_policy | 05页任务、语言/市场/受众/评级与范围摘要 |
| Segment或获准流转的源Candidate | source_spans、segment_id、输入修订、文本/时间、目标variant | Candidate的input_revision、target_variant_key及源句对照 |
| 上下文09返回的受控材料 | 角色/场景、适用锁词、已确认历史译法、缺项、版本/校验值 | Run.context_manifest；term_hits与差异依据 |
| 模型与检查结果 | 确切模型/Prompt、QE版本与模式、关键实体比对 | text候选、confidence实际来源、Issue及检查解释 |
| 人工决定08 | before/after引用、权限/版本校验与reason_code | 新目标修订/驳回原因；不原位改Candidate |

输出使用既有Candidate、Issue、Run及其input_refs/output_refs。候选不可变，新译文另建candidate_id并关联supersedes_candidate_id；一个源段的多个目标分支彼此隔离，不覆盖源稿或其他市场稿。

## 3. 处理步骤与交接

1. 核对已确认Task、母版关系、范围、源输入和目标variant；默认读已确认源修订。中间源候选仅在有效预授权覆盖且该阶段准入/检查通过时可读，引用具体Candidate，状态仍为AI_PROPOSED。
2. 向09请求本句所需角色/场景、锁词及历史译法。先检查访问权、适用范围和有效版本，再形成manifest；材料缺失标明影响，必需上下文不足时等待补料，不让模型补造人物关系。
3. 将适用锁定译法作为生成约束。局部窗口按已批准策略选择；RULE-TR-003的前后句做法是规则设计基线，实际窗口/扩窗额度待确认，不盲塞整片。
4. 模型仅产出目标语候选及解释。代码校验结构、语言分支、锁词命中、数字/否定/实体变化；QE在已选模型、模式和校准依据下辅助路由，不把分数当正确概率。
5. 锁词漏用阻断该候选；称谓/跨集译法冲突列出双方来源待人核实。关键语义疑似变化挂Issue必审；确定丢失否定、数字或实体时不可作为合格候选推进。
6. 保存成功才回传候选和实际检查范围。默认译员审阅后交文化/单位等适用模块；满足有效预授权与准入时可交中间候选，不能写人工接受事件或HUMAN_APPROVED。

交接携带Task快照、源/目标Ref、variant、manifest、检查结果、未决Issue及责任；04/05/06读取确切输出。无合格译文时返回真实失败/待人工，不用空字符串冒充翻译完成。

## 4. 页面动作与反馈

对应[05初翻与本地化候选](../02-prototype/pages/05-translation.html)的翻译区域；同页单位区由功能05负责。静态示例不能作为真实保存、模型质量或权限证据。

| 动作 | 页面反馈 | 执行端约束 |
| --- | --- | --- |
| 查看源句/候选 | 并排源文本、目标文本、片段时间及版本；默认折叠技术引用 | 查询仍检查项目/对象读取权 |
| 展开锁词/冲突 | 显示源词、要求译法、实际译法、上次确认位置及版本 | 不由模型选择哪个锁词版本生效 |
| 发起翻译/重译 | 处理中防重复提交；成功后展示新候选，失败保留旧稿和原因 | 重译须明确范围及新运行条件，控制由10复查 |
| 接受/编辑/驳回 | 转08处理；编辑完成可保存并提交待审，有审核权限的真人明确接受才有审核通过结果 | 锁词/语义阻断不可直接普通接受；逐条校验版本与权限 |
| 批量处理/继续 | 按条显示成功、拒绝或待补；交接显示具体输出引用 | 不将含失败整批标成功；继续不是内容已确认 |

保存失败保留未提交编辑；并发冲突展示当前修订和待提交差异，不静默合并。锁定/人工确认稿只读，另存候选入口保留。

## 5. 工具、模型与人工边界

| 主体 | 负责 | 边界 |
| --- | --- | --- |
| 代码/工程工具 | 引用与结构、锁词命中、实体信号、版本与准入检查 | 命中检查不是完整语义裁决；未知分词/词形不硬判正确 |
| 翻译/QE模型 | 生成、解释、忠实度信号 | 不改术语活动包、不自授权限、不以自信绕过硬规则 |
| 译审/负责人 | 忠实与称谓裁决、补料、手译、申请新词条 | 普通编辑不能修改锁词定义；变更规则走09治理 |

运行固定模型、Prompt、术语、规则和输入校验值；不使用模型的写入权限直接改确认稿。无需使用的工具/模型在manifest注明not_used，不虚构调用。

## 6. 局部异常与恢复

| 触发 | 处理 | 恢复条件/责任 |
| --- | --- | --- |
| 缺角色、历史译法或上下文冲突 | 保留原文/旧候选，列缺项及受影响句；不猜性别/称谓 | 负责人补受控引用或人工核实，再按新manifest重跑受影响范围 |
| QE缺模型/校准、规则未有效 | 未评估/待检查，不填虚构分数、不默认自动通过 | 配置合格评价依据或走明确人工路线；仍保留硬检查 |
| 超时、非法结构、空输出 | 记录失败attempt及实际费用；不创建成功候选 | 可重试错误交10，预算或连续重试停止不能被重译按钮绕过 |
| 锁词与模型意见相反 | 保留锁词阻断及模型解释 | 有权人核实适用性；换词条版本需新manifest/Run |
| 输入改版/授权撤销/锁定写入 | 拒绝旧版写入或越权，已产候选保留 | 08处理新修订，10重验授权，只复检受影响依赖 |

## 7. 能力接口、追踪与指标

下表是逻辑能力契约，不规定HTTP地址、传输协议或已实现服务。

| 能力 | 请求与前置 | 返回/失败语义 |
| --- | --- | --- |
| 申请初翻/局部重译 | Task修订、源Ref、目标variant、范围、上下文/规则及执行许可引用 | Run和受理/等待/拒绝原因；不会直接伪称翻译成功 |
| 读取翻译结果 | 已授权Run/候选Ref | 候选、term_hits、检查与Issue、版本；无权不泄露其他项目 |
| 交接审阅/下游 | 确切输出Ref及检查、manifest、未决项 | 受理范围/阻断原因；08决定内容，10判断可否执行 |

通过task_id/trace_id/run_id及`(run_id,attempt_no,step_id)`定位上下文组装、生成、检查和交接；保留失败、耗时、usage及真实错误。相同有效幂等结果只交接一次，事件去重不能代替执行幂等。

沿用`run.started/run.finished`、`candidate.created`；真实可见才有`suggestion.shown`，08的人工决定用`review.decided/review.blocked`，实际评测用`quality.assessed`。不新增同义事件；未知成本不记0。

引用MET-TR-001、MET-QUAL-004及MET-GOV-001；QE按冻结版本/模式报告覆盖，术语按适用出现次数计算。缺金标不声称忠实准确，未审、缺项、失败单列，公式/窗口/去重仅引用metrics。
