## 3. 输入、输出与版本契约

| 契约 | 必要引用/数据 | 拒绝或交接规则 |
| --- | --- | --- |
| 审阅输入 | project/Task及task_revision、Media；Segment的segment_id、variant_key、revision；Candidate的ID/固定修订及input_revision | 必须同项目且能访问；目标分支必须在任务中定义，不按语言猜分支 |
| 判断依据 | Issue、source_spans、音画/上下文Ref、规则/版本、模型与Prompt来源 | 缺失明确标识；不能借备注宣称完成必审或证据核验 |
| 写入前提 | action、target_refs、before_ref、expected_revision、reason_code、权限检查引用 | 对确切分支复查当前修订、锁定、任务与动作权限；旧版拒绝 |
| 内容输出 | 追加Segment修订及受控当前指针；原Candidate保留；相应ReviewDecision | 不原位改候选或历史确认稿；草稿不产生HUMAN_APPROVED |
| 决定输出 | decision_id、actor/role、occurred_at、before/after_ref、相关候选/片段、permission_check_ref | 实际成功才记决定；失败留review.blocked，不造成功decision_id |
| 关联输出 | batch_id、supersedes_decision_id、undoes_decision_id及Event | 批量按项、撤销指原决定；原事件保留，错误不抹去 |

字段类型/枚举以schema为权威。候选内容不可变，候选修改另建candidate_id；人修改保存为人工修订。源语用source分支，目标用任务variant_key；不能用Segment.current_revision更新所有语言。

## 4. 单条动作与状态

1. 读取确切候选、当前稿、问题和依据，显示是否可处理及原因。
2. 有权人选择动作，检查该动作所需的必审/补证与保护条件；人工判断不由模型代签。
3. 服务端在提交点再次检查权限、expected_revision及目标分支；成功才追加决定和内容修订，更新受控投影。
4. 返回持久结果及受影响下游；失败不更新成功态，未完成问题保留并交责任人。

| 动作 | 持久结果及状态含义 | 不能据此声称 |
| --- | --- | --- |
| accept | 有权人工直接接受有效候选，另建origin=ai_accepted修订；候选ACCEPTED，人工稿HUMAN_APPROVED | 模型正确、技术检查通过或已签发 |
| edit | 另建origin=human_edit编辑修订并留edit决定；保存可继续编辑，保存并提交后为编辑完成/待审，追加review.submitted | 审核通过或人工已确认；提交者默认无审核权，候选不因保存/提交就转ACCEPTED |
| edit_accept | 有审核权限的真人核实并确认指定编辑成果，引用准确修订及原候选；候选EDITED_ACCEPTED | 直接接受；未审范围同时完成 |
| reject | 候选REJECTED，原稿不被删除；记录原因与问题后续责任 | 自动生成正确稿、自动重跑或问题自动解除 |
| escalate | 候选ESCALATED，Issue交相应有权职责，保留原因/证据/责任 | 普通译审已裁决、风险已消除 |
| skip | 人工明确暂跳，留原因；未审/未决仍保留 | 已审成功；系统自动跳过不得伪装该决定 |

编辑中的保存与编辑完成提交分开；提交表示本环节做完、交审核区，待审仍显示NEEDS_REVIEW，不表示工作没做完，也不复用上一版HUMAN_APPROVED。保存/提交与审核分别检查权限并保留准确修订。无候选人工补写后的明确确认方式按既有ReviewDecision/Segment记录承接，序列化需评审，不临时增加动作枚举。

预授权只允许符合准入的中间AI_PROPOSED继续下游，不生成假accept/人工状态。母版、最终内容确认及签发仍须有权人工；签发权限由07/10分别承接，不能以本页“接受”代替。

## 5. 批量、锁定与并发

批量选择按片段/分支/候选固定，预览列每项expected_revision与判断结果。必审未完成、证据缺失、已有人工确认/锁定稿、无权或过期项不进入默认批量直接接受。

提交时逐条复查；可保存项各自形成决定，共享batch_id/operation_id；单项事务保证决定与对应内容一致。某项冲突不回退其他已成功项，也不显示整批成功。仅人工明确skip才记skip决定，其余跳过/失败使用review.blocked。

| 情况 | 处理 |
| --- | --- |
| Agent重跑面对HUMAN_APPROVED/MANUAL_LOCKED | 只能另存AI_PROPOSED；禁止写当前正文或解除锁定 |
| 有权人工修改确认/锁定稿 | 先明确人工变更范围与原因，另建修订；锁定不是普通编辑的隐式解除 |
| 相同分支两人同时保存 | 第一个有效提交成功；另一份expected_revision过期拒绝，保留编辑供对比 |
| 不同目标分支同时操作 | 各自校验分支修订与权限；不得误用源语current_revision覆盖另一分支 |
| 预览后权限撤销/版本变化 | 保存点拒绝相关项；原预览不能作为写入许可 |
| 确认/锁定专门操作 | 保护语义沿用schema；锁定/解锁尚无独立ReviewDecision动作，具体记录映射待评审 |

锁定/解锁记录方案未确定前，不实现无审计的切换或借edit/revoke随意解除。具体角色等级待定；有权人工也不能跳过质量硬阻断。

批量选择范围须在预览时明确：当前筛选中实际选中的候选及分支，不把未加载记录静默加入。更换任务、母版、目标分支或筛选后重新预览；已完成项不因刷新再次接受。

批量结果同时返回已成功、自动跳过、保存失败的逐项清单及计数；成功项可定位决定/修订，失败项可定位原因与重试入口。重试只处理有权且仍有效的失败项，不能重复生成成功决定。

版本冲突后的“重新对比”展示当前稿、旧候选和未提交草稿三方差异；用户主动重新选择/编辑后以新的expected_revision提交。系统不自动将旧编辑套到新稿，也不静默合并否定、数字、时间轴或人物信息。

## 6. 局部修复、撤销与回滚

| 步骤 | 用户与系统行为 | 交接 |
| --- | --- | --- |
| 定位 | 从片段、问题或文件行定位当前/历史分支、Candidate及Run/attempt/step | 先确定错误源头，不默认整链重跑 |
| 提议修复 | 人编辑新草稿，或在10授权内申请指定范围新候选 | 旧确认稿和旧候选保留；模型不能直接覆写 |
| 撤销决定 | 有权人选原决定、说明原因，记录undoes_decision_id及新决定 | 不删除原决定；已派生内容需另建修订处理，不能只改统计结局 |
| 回滚 | 对比当前r与历史h，有权人确认后把h内容复制为新r+1 | rollback决定含原/新引用，current指向新修订；历史h不变 |
| 影响分析 | 用input_refs/source_refs定位依赖片段/分支的候选、Issue、Validation与Artifact/签名 | 旧PASS/签名不适用于新修订；保留历史并列待复检清单 |
| 恢复交接 | 对受影响范围重新确认/检查、生成文件并按需重新签发 | 无关范围不全量重跑；新稿不借旧包合格态直接交付 |

已外部提交/发布的内容，本地回滚不能自动撤回。07记录外部事实并按约定返工/新交付关联；COMPLETED/CANCELLED任务的后续工作按主PRD另建关联任务，不重写已结束任务。

## 7. 能力接口、异常与恢复

接口是能力契约，实际HTTP/函数/队列形式待技术方案，不创建接口路径。

| 能力 | 输入 → 输出 | 失败去向 |
| --- | --- | --- |
| 读取审阅上下文/历史 | 同项目Task、片段分支/修订及权限 → 当前稿、候选、问题、差异、可操作项 | 无权拒绝且不泄露其他项目；引用缺失交负责人补证 |
| 保存单项/批量决定 | 动作、确切Ref、expected_revision、原因及操作防重引用 → 逐项决定/新修订/影响列表 | 返回无权、旧版、未决、保存失败；重送查原结果 |
| 查询版本影响 | 变更before/after Ref → 依赖候选、检查、文件/签发引用及待处理范围 | 依赖记录不全报不可判定；相关交付不当作仍有效 |
| 撤销/回滚 | 原决定/历史版、当前expected_revision、原因及权限 → 新决定/修订/复检交接 | 新冲突先刷新比较；禁止删除历史伪装恢复 |

权限检查/存储不可用时不写成功决定；人可继续查看有权缓存和保留未提交草稿，恢复后重新校验。问题裁决内容由04/06等主责，本文只统一升级与留痕。关键规则冲突不能靠重复点击接受消除。

## 8. 追踪与指标

实际展示发suggestion.shown；编辑提交发review.submitted且不计审核成功；实际审核决定发review.decided，失败/自动阻断发review.blocked，撤销/回滚发review.reverted，敏感动作保留permission.checked，人工活动按human.activity记录。候选未展示不造展示事件；授权动作不混入字幕接受事件。

MET-REV-001/002区分直接与修改后接受、撤销及完整7日观察；MET-REV-003按已审事件计算编辑，纯时间编辑/人工补写另列；MET-REV-004保留驳回原因。MET-GOV-001/002观察血缘完整与越权成功；公式、去重和窗口只引用metrics，不在本文设新阈值。

## 9. 验收与待定

下表每格是待细化的验收场景；正常/异常/权限三类状态全部NOT_RUN，非正式TC、非执行证据。6条局部需求共18项，不与继承的主AC重复计数。

| 局部场景 | 正常 N（NOT_RUN） | 异常 E（NOT_RUN） | 权限 A（NOT_RUN） |
| --- | --- | --- | --- |
| REV-01 P0 | 有效候选接受或编辑后确认→新修订且两类接受分开 | 草稿保存/驳回→不假称确认，未决保留 | 无内容确认权→拒绝决定写入，草稿不升级确认 |
| REV-02 P1 | 合法批量→按条决定且共享batch_id | 一条旧版/缺证据→该条失败/跳过，其他逐项反馈 | 预览后某项撤权→该项拒绝，其他仍独立检查 |
| REV-03 P0 | 有权人工修订→保留旧稿及分支版本 | 同分支并发→旧expected_revision拒绝并保留编辑 | Agent改人工锁定稿→拒绝，只能另存候选 |
| REV-04 P0 | 回滚历史内容→新修订并列受影响复检 | 依赖不全→相关交付待核，旧PASS不作新稿证据 | 无回滚权/跨项目历史→拒绝且不泄露正文 |
| REV-05 P0 | 有权人补证裁决→依据留痕后再审阅 | 未决风险→保留责任/阻断，不自动消失 | 普通译审越过升级裁决→拒绝解除阻断 |
| REV-06 P0 | 有权人保存决定且已形成结果→从当前稿回查候选、输入、主体和后续版本 | 保存失败/重送→失败不计接受且成功只记一次 | 无历史访问权→拒绝读取审阅正文与证据 |

## 2026-10-21确认：编辑区与审核区

编辑角色默认仅可生成、保存、提交成果，不能自授审核权。审核主体读取确切提交修订、声音/源稿和必要依据，允许通过/退回；退回保留原成果与原因，编辑后形成新修订再提交。中间审核Agent可给复核候选/疑点，不能代替最终真人终审。一个人只有分别获得两项权限才可兼任，保存不隐式审核。现有§6“定位→人修订/申请AI候选→复检”足够，不加入Agent自主修改代码/规则、自修复循环。
