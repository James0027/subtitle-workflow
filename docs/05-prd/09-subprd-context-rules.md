## 1. 职责、入口与需求

为已确认Task及指定模块取得有权读取、适用且可追溯的上下文/规则版本，并将选用、缺失和冲突交给调用方。本文负责供给与引用，不负责翻译生成、文化裁决、终稿确认或规则自动生效。

入口为02任务单资料/市场/profile选择、05术语/上下文说明、06风险证据、07终稿依据与各模块执行前组装。首批服务源语所需素材、角色/术语及源语交付规范；目标市场/翻译专用包随03—06后续接入。

复用Asset受控引用、Task条件、Run.context_manifest和既有规则登记。当前不新建向量库、独立知识库、管理后台、自动联网抓取或组织权限系统；查找先用现有有权资料与版本引用。

| --- | --- | --- |
| 任务引用资料 | 选择同项目已授权资料；查看来源、版本、作用范围和缺项 | 保存任务修订；缺角色不自动编角色，缺必需目标条件显示待补 |

| 无权/不可用 | 显示本项目需要补资料或申请有权人处理 | 不泄露他项目标题、正文、命中数量、存储地址或存在性 |

加载失败保留已选引用和未提交说明；重试先校验权限与版本，不用默认包替换失败结果。页面可浏览说明不代表执行端已获使用/外传许可。

## 3. 输入输出与承载

| 契约 | 既有数据承载 | 条件与输出 |
| --- | --- | --- |
| 调用范围 | Task.project_id/task_revision、task_type、module_plan、source_locale、range、target_variants | 明确模块及目标variant；源语不适用市场条件须有理由，多语不以语言推市场 |
| 输入文字/声音 | Segment分支修订、Candidate固定版本、source_spans；Asset/Media Ref | 仅选定任务范围及可访问来源；依赖候选时保持其AI_PROPOSED身份 |
| 项目资料 | Asset(kind=character/terminology/style_guide/script等)、来源/版本/checksum/privacy | 按title/episode和授权用途筛选，不整库注入；未知状态保留 |
| 目标约束 | Task中的regulatory_pack_ref、platform_profile_ref、受众/评级 | 按确切ID/版本及市场匹配；未知不伪造version，不凭示例profile放行 |
| 规则元数据 | rule-registry§2登记结构，rule_id/version、状态、scope、来源、时间及审批 | 活动集需已批准且适用/有效；本项目DRAFT规则不冒称已启用 |
| 固定依据 | Run.context_manifest/manifest_hash、输入Ref/checksum、模型/Prompt/工具/规则/校准版本 | 明确used/not_used及缺失状态；无调用不造模型或token数据 |
| 问题/反馈 | Task.missing_items/readiness、Issue及Event.payload/subject_refs | 缺项按影响阶段交owner；冲突保留competing_refs及原因，不新增上下文实体 |

Ref内容修订必须明确revision；Segment另带variant_key。Task的包/profile引用与manifest中id/version/checksum/status须可互相校验，序列化及内容快照取得方式在实现前冻结，不用自由字符串代替可核验版本。

## 4. 组装步骤与判定

1. 校验调用主体、项目/对象访问权、用途及外传约束。检索前过滤、读取/注入前复查；缓存命中也不绕过权限。
2. 固定Task快照、模块、片段范围/分支及输入修订；检查该模块所需资料清单，未知不自动记不适用。
3. 取得当前句及必要邻句、关联角色/场景/术语；只取支持本次判断的材料，保留每条来源与版本。
4. 核验市场、受众/评级、平台/profile及规则有效性，形成适用/不适用/缺失/冲突明细。
5. 调用方运行前固定manifest/hash，并完成10的权限、准入/预算检查；缺必要依据不启动依赖步骤。
6. 模块输出引用实际使用依据；人可由结果回查版本。补料/更新后重新检查并新建相应Run，不改旧记录。

| 上下文层 | 取得与使用 | 缺失或不确定时 |
| --- | --- | --- |
| 项目层 | 角色、剧情、风格、锁定术语按作品/集数及语种作用域 | 相关判断标NEEDS_CONTEXT；角色身份未知，不强配speaker |
| 片段层 | 当前片段及规则登记要求的局部窗口，必要时引用场景/音画 | 当前规则含前后各2句的设计窗口；实际可得量如实记录，不凑邻句或盲塞整片 |
| 市场层 | 精确market及评级、内容/风险类别匹配包 | 未知/过期不默认适用；P0相关范围阻断并升级 |
| 平台层 | 固定profile版本；技术检查取完整相关项，口语取可读性子集 | 不用公开通用示例替代本任务规范；所需项缺失则不签合格包 |
| 历史层 | 仅已人工确认译法、已裁决记录及已生效规则，带决定来源 | 驳回历史仅作有来源提示，不自动学成新规则；跨集冲突留待裁决 |
| 禁止层 | 其他项目机密、未授权个人信息、无来源论坛意见不注入 | 拒绝并留脱敏审计；日志不复制正文/签名URL/凭据 |

默认窗口不等于一律足够；扩大范围需记录新来源/权限和context hash，重新判定调用/费用资格。OCR/画面资料只引用实际已提供且有权的结果，不新增视觉识别承诺。

## 5. 规则选择、冲突与版本

规则状态沿用DRAFT/APPROVED/ACTIVE/RETIRED；候选包、课堂例子或普通编辑不能直接变ACTIVE。生效和变更由规则责任人按登记流程审批，本子PRD不提供免评测的一键发布。

| 判定顺序 | 处理 | 留痕 |
| --- | --- | --- |
| 系统不变量 | 人工稿保护、权限、输入修订与停止条件优先 | 规则/Prompt不能覆盖RULE-SUB-001—004 |
| 来源/时间/范围 | 核验来源快照、版本、状态、生效/过期及所有必需scope维度 | 缺失=NEEDS_CONTEXT；不适用=SKIP；读取错误=ERROR，不能都算通过 |
| 硬约束并存 | 适用的确定性硬要求必须同时满足 | 无法并存BLOCK，展示全部冲突及责任；不删其中一条 |
| 可覆盖政策族 | 仅在允许覆盖同一决策内按规则登记优先级/可比较scope specificity选择 | 记录命中、并存、被覆盖规则和理由，不按数组/版本大小选胜者 |
| 不可比/同级相反 | 保留RULE_CONFLICT并升级senior/legal等有权职责 | 不重试同配置，不让模型自评裁决法律或平台冲突 |

语言不等于国家/市场；两目标市场不同规则应拆任务分支。普通市场偏好不能自封法律依据。模型未发现风险不证明无风险；模型认为通过不能消除有效硬命中。

每个Run固定活动集快照；规则/术语/Prompt更新不热切换。旧manifest必须能解释当时使用何版；新包生效后，按依赖Ref/hash定位受影响候选、检查和文件，交08/07复审/复检。不是全量历史统一改写。

版本固定保障历史解释，不能作为未来继续使用已失效规则的许可。后续敏感动作仍需核验当前有效性；运行中发现失效/撤回时停止依赖的继续动作，保留原快照和当时结果，交owner明确受影响范围。

内容资料与执行规则分别展示：角色表、剧情摘要提供语境，不自动拥有法律/平台约束效力；规则包提供有范围的约束，也不能代替当前片段语境。人物说某句话不等于作品或项目认可该立场。

上下文输出中的“完整”只说明本次必需资料项和引用可用，不说明模型已正确理解。模块仍须记录实际使用的术语/规则命中，08/04仍负责人工审核与裁决。

源语非平台交付可按已确认任务显式不适用特定市场/profile；这与多语任务缺市场包不同。调用方必须提交不适用依据，不能用空值混过适用检查。

## 6. 缺失、失效、恢复与权限

| 情况 | 当前处理 | 责任/恢复 |
| --- | --- | --- |
| 非当前阶段必需的脚本/角色资料未交 | 登记缺项及受影响判断，不一律阻断ASR | 素材/任务负责人补料或安排人工核实；相关专名/语义仍必审 |
| 本模块必需语境或锁词版本缺失 | 该判断NEEDS_CONTEXT，不猜补，不默认自动继续 | 负责人补可核验来源；重新检查、组装并引用新manifest |
| 市场包/profile无版本、过期或不可读 | 依赖路线阻断；P0不降为只读默认包放行 | 规则owner确认有效包或有权裁决；不因授权覆盖缺规范 |
| 多份依据冲突 | 展示双方来源/范围/版本和影响片段，保持未决 | 有权人补证/裁决，批准新依据后新运行，旧冲突保留 |
| 权限撤销或跨项目缓存 | 拒绝后续读取/注入及依赖动作 | 有权人重新处理许可；不能复制缓存到本项目绕过隔离 |
| 原来源失效/旧模型不可得 | 保留已有受控快照/hash及无法复现原因 | 不伪称完整重现；必要时新版本重新核验，旧产物解释边界明确 |

补证不自动清除风险；04负责风险判断，08负责有权决定，07负责交付闸门。无预算/外传授权时不能借补上下文启动付费或外部检索。

## 7. 能力接口与追踪

以下为能力接口，不规定HTTP路径、数据库或检索产品。

| 能力 | 输入 → 输出 | 错误/权限约束 |
| --- | --- | --- |
| 获取有权上下文 | project/Task快照、模块、输入Ref/分支、范围、主体 → 有来源版本的最小资料集/缺项 | 先过滤权限，再取正文；不得返回他项目命中信息 |
| 解析适用规则/profile | 任务市场/受众/评级/平台与规则引用 → 固定活动集、scope结果、冲突及来源 | 缺维度/版本不可判适用；不给默认通用包绿灯 |
| 固定/回查manifest | 实际输入、资料与模型/工具/规则版本 → manifest/hash及来源明细 | 缺必要引用阻断；历史不可热改；hash序列化待冻结 |
| 查询变更影响 | 新旧版本Ref/hash → 受影响Run/候选/校验/文件引用 | 权限限定项目；依赖不全列未知并交负责人核查 |

敏感读取/注入按permission.checked留主体、动作、目标版本及结果；Run记录实际context_manifest，Issue记录来源、证据状态及冲突引用。只引用既有事件，不新增“知识命中成功”事件或独立日志表。

MET-GOV-001检查最终片段/产物的必备引用完整；MET-GOV-002记录越权成功；MET-QUAL-005区分证据形式完整与人工核验有效；MET-QUAL-004由翻译模块记录锁词出现级结果。本子PRD不把“检索有结果”当风险正确率或字幕合格率。

| CTX-05 P0 | 有权补证且复查通过→仅恢复对应范围 | 硬规则不可并存→保留BLOCK并升级 | 普通译审/模型裁决冲突→拒绝解除阻断 |
