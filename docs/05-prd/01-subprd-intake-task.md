## 1. 范围与需求

本功能从登记收到的素材开始，到有权人员确认母版及任务、完成当前阶段就绪检查为止。先创建真实任务草稿并取得稳定ID，再进行素材准备/抽轨和母版确认；母版与任务正式确认后才允许ASR等业务处理。不进行ASR、翻译、终审或文件签发，不新增媒资后台或组织权限系统。

首批是源语闭环；多语字段和单模块入口只定义兼容边界，不承诺本批提供所有模块。最终人工确认及预授权原则继承主PRD，不在本文改写。

## 2. 页面与操作

对应现有[01素材与母版](../02-prototype/pages/01-intake.html)、[02任务单与开工](../02-prototype/pages/02-task.html)。页面布局沿用V3；下表为真实产品目标行为，静态页面本身不执行保存或流转。

| 区域 | 展示/操作 | 保存后反馈与联动 |
| --- | --- | --- |
| 01 素材入口与清单 | 选项目、提交或引用已授权文件；看类型、来源、状态、版本和检查依据 | 实际接收成功才出现Asset；失败保留原因/重试入口，不显示“母版已确认” |
| 01 母版核对 | 明确作品/集数、视频、主声音及附件关系；查看技术检查并音画核对 | 有权人明确确认后显示确认主体、时间及母版ID；02引用该母版 |
| 01 内容资料 | 查看/补充题材、内容形式、原内容评级、对白密度和参考材料 | 未知保持未知；显示来源/测量状态；不以模型猜测替代负责人确认 |
| 02 任务编辑 | 明确范围/路线/输出/责任及适用语言市场条件 | 保存仅产生草稿/修订；缺项集中显示“缺什么、影响哪里、由谁处理” |
| 02 任务确认 | 预览当前母版、处理内容、输出、责任和缺项处理 | 有权人确认准确快照；不因点过确认就跳过阶段检查 |
| 02 就绪与交接 | 查看当前阶段检查、逐次确认/预授权方式及可执行范围 | 条件不齐定位字段或素材；无授权给请求入口；符合条件才可申请03处理 |

保存/确认请求中显示处理中，成功响应后再更新摘要。失败保留用户未提交编辑及重试入口；版本冲突先取当前版本对比，不静默覆盖。只读用户可看有权对象，操作不可用时说明原因；执行端必须独立校验，隐藏按钮不算权限控制。

## 3. 收料与母版确认

### 3.1 登记与检查

1. 接收前校验项目访问权及用途授权。来源/授权不明时提示补证，不伪造`rights_ref`创建可用Asset，也不把文件送外部工具。未收到的附件记缺项，不造空Asset。
2. 收到文件后生成受控引用，保存原件、校验值、类型、提供方版本和隐私约束。可读性、时长/帧率、声音等由工程工具实测；未测保留unknown/null，不补0或假PASS。
3. 音轨可独立提供，也可来自视频。提取成功另存派生Asset，绑定父文件、工具/参数及执行引用，原视频不覆盖；提取失败不得登记为可用声音。
4. 对照作品、集数、剪辑、声音、脚本/字幕版本关系。校验值相同只证明字节相同；不能证明配套、音画对应或字幕内容正确。有声不等于可供ASR使用，细化音质准入由02子PRD承接。

相同项目、同一次接收请求重送应返回原接收结果；同文件再次提供仍须核实用途/配套关系，不自动新建母版或改变已确认母版。文件跨项目复用必须重新取得相应访问/使用许可，不能借去重结果泄露他项目是否存在该文件。

### 3.2 母版确认条件与状态

| 判定 | 满足条件 | 不满足时 |
| --- | --- | --- |
| 内容身份 | `title_id/episode_id`明确，视频可用，素材属于本项目 | 可先登记素材；母版保持待补/待核对，不按文件名猜集数 |
| 技术与声音 | 时长/帧率与时间基准实测；主声音存在且来源对应 | 无独立音轨可先提取；无可用声音阻断从零转写，不用预授权绕过 |
| 配套与疑问 | 已提供附件的来源/版本关系可查，错配已解除或明确不选用；缺脚本等有缺项责任 | 必需关系未知或错版不确认；可选附件未交不统一阻断 |
| 最终决定 | 有母版确认权的人查看当前核对结果并明确确认 | 工程检查或模型建议不能代签；无权者返回拒绝/申请处理 |

`master_status`沿用schema：REGISTERED表示已登记；待核对/检查失败为NEEDS_REVIEW；有权人工确认后为CONFIRMED；历史母版退役为RETIRED。已有CONFIRMED母版发生剪辑/画面/主声音替换时另建Media，通过`supersedes_media_id`关联，不能覆盖原件后沿用旧确认。

新流程母版确认绑定已创建的真实Task草稿；草稿ID即任务ID，确认后不换号。抽轨由获准ingest Run完成并保留父Asset、工具/参数/输入输出；之后确认母版与Task。不得把草稿当已确认而启动ASR。

## 4. 任务内容、缺项与确认

### 4.1 字段与页面的数据对应

以下只列使用位置和业务判断；类型、缺失值及唯一约束以[schema§3](../03-foundation/schema.md)为准。不新增同义字段或把整份字段表复制进PRD。

| 页面信息 | 读取/写入字段 | 确认时的业务判断 |
| --- | --- | --- |
| 素材来源与可用性 | Asset的`source_uri/rights_ref/origin/availability/privacy/inspection` | 仅引用同项目且允许本用途的素材；实际需外部处理时另查外传许可 |
| 母版摘要 | Media的`media_id/title_id/episode_id/master_video_asset_id/primary_audio_asset_id/duration_ms/frame_rate/match_checks` | 确切已确认母版，不用“最新文件”模糊引用 |
| 内容资料 | Media.`content_dimensions`；角色/术语/脚本等Asset引用 | 题材/形式/原评级按来源保留；测量值有方法/版本；原评级不替代目标市场评级 |
| 任务归属和责任 | `project_id/media_id/purpose/owner_id/parent_task_id` | 用途和负责人明确；确有父任务才关联，单模块不强制造多语父任务 |
| 业务范围与调用方式 | `task_type/execution_mode/module_plan` | 明选source_only或multilingual；workflow或module_only；各模块required/not_applicable/deferred有理由 |
| 源语处理 | `source_locale/processing_route/input_asset_ids/range` | 明选transcribe/verify_existing/align_existing；指定声音及已有字幕/源稿角色；whole取实测时长，区间合法且不越界/不重叠 |
| 目标要求 | `target_scope_status/target_variants` | 源语显式not_applicable并说明；多语须specified且语言/市场/受众/评级/适用规则齐备，不用语言代替市场 |
| 输出与交付项 | `output_spec/delivery_units` | 明确格式/用途/分支/范围/交付项；平台验收须确切profile；非平台源语可明确不适用，不留含糊空值 |
| 审核/执行方式 | `execution_policy`及授权引用 | 默认manual；预授权范围由有权人员确认，具体等级后补；负责人身份不自动代表拥有全部权限 |
| 缺项与阶段反馈 | `missing_items/readiness/task_status` | 显示缺项原因/影响阶段/责任/处理依据；状态来自实际检查，不由前端自行判绿 |
| 修订与确认 | `task_revision/request_key/confirmed_by/confirmed_at` | 保存和确认分开；确认绑定准确快照，变更后重新确认 |

已有字幕不默认重做ASR。文字核对或时间对齐必须明确使用哪份已有字幕；从零转写必须有可用声音。已有外部源稿可登记并核实后提供给相应模块，不要求由本系统生成。

### 4.2 缺项如何处理

| 情况 | 处理和责任 | 能否确认/开始 |
| --- | --- | --- |
| 缺脚本、角色或术语资料 | 登记未交/未知及影响；负责人安排补料或人工核实 | 不统一阻断ASR；若影响专名/语义判断，交接必审/补证，不猜补 |
| 无独立音轨，视频有可用声音 | 提取并验证派生音轨，记录与母版关系 | 不要求用户重复交一份音轨；提取成功且其他条件齐备才开始 |
| 无可用声音/错剪辑音轨 | 列出素材问题、受影响路线和补料责任 | 阻断从零ASR；人工修复/另选任务后重新检查，不能假称机器已生成 |
| 已有字幕路线但缺所选字幕 | 提示指定或补交当前版本 | 相应核对/对齐不可开始；不能偷偷改为转写 |
| 多语任务目标未定 | 保留草稿和目标缺项，负责人补齐 | 不确认该多语任务，不自动降为source_only；另建明确任务须用户主动选择 |
| 未设置承诺时间 | `due_at=null`，显示未约定 | 可保留真实任务事实；不能评价准时达标或伪造SLA |
| 原评级/对白密度未知 | 显示未提供/未测和影响阶段 | 不填示例值；若当前阶段不依赖可继续，目标受众/评级仍须另确认 |

`missing_items.resolution_status`只反映处理事实：补齐并验证后resolved；明确可选/不适用且有权人给出理由及引用后才可waived。必需声音、任务确认、权限、硬规则不能靠“豁免”跳过；处理/豁免后仍重做相应就绪检查。

### 4.3 保存与任务确认

草稿可先准备，不要求当场齐料。确认时服务端核对当前任务修订、已确认母版、必填任务定义及条件字段；有权人查看摘要后提交`confirm_task`，成功保存决定、确认人/时间和确切快照，才记录`task.confirmed`。校验失败保留草稿、列具体缺项，不落虚假确认事件。

任务目标已确认不等于全链所有材料/运行条件已就绪：例如后续语境资料可列对应阻断阶段。多语业务目标本身未定则仍不能确认任务；不得借“分阶段”把未定义任务送入ASR。

## 5. 就绪检查与交接

| 检查顺序 | 执行判定 | 失败反馈 |
| --- | --- | --- |
| 1 对象和版本 | 请求项目/任务/母版及输入引用真实存在且版本一致，任务与母版已确认 | 返回缺项/冲突及引用；无任务不创建ASR运行 |
| 2 当前阶段输入 | 处理路线、范围、声音/已有字幕等必需输入符合条件，内容缺项按影响阶段判断 | readiness为blocked或待检查pending，列补料责任 |
| 3 规则与质量条件 | 当前所用规范有效，适用模块及准入策略明确 | 未判断不能标not_applicable；未测不记PASS |
| 4 身份与授权 | 执行主体对对象/工具/动作有权；逐次确认或有效预授权覆盖本次范围 | 显示未授权/撤销/越范围及请求入口，不把任务负责人默认当管理员 |
| 5 预算与停止条件 | 实际启动前复查预算、重试/停止和外部处理许可 | 未配置不启付费自动路线，保留就绪/停止原因；细则由10承接 |

检查记录写`readiness.checked`；条件齐备时按既有状态机进入READY并记录`task.ready`。保存任务、母版确认、预授权、就绪和发起执行是不同动作；一次点击可依序组织，但每项必须实际成功才能继续，不合成一条虚假“全流程通过”。

申请启动时仍由执行端重查当前版本、权限及控制条件。`task.ready`或旧PASS不是永久通行证；从READY实际执行进入IN_PROGRESS及Run创建由10/02承接。检查通过但没有实际启动时，不记录`run.started`或已扣费。

交给02/执行能力的数据为：确切Task快照、Media及选用Asset引用、处理路线和范围、必要上下文/规则引用、当前readiness依据、缺项及责任、执行策略/许可。接口按schema Ref使用版本；任务被修订后禁止用旧快照悄悄绑定新运行。

## 6. 异常、变更与权限

| 触发 | 系统动作 | 人工处理/恢复 |
| --- | --- | --- |
| 文件损坏/不可读/接收中断 | 不显示可用，保留实际接收与失败状态；不创建成功检查 | 重传或提供可用文件，保留原记录；不自动调用模型修复素材 |
| 版本错配或脚本与成片不符 | 展示文件/版本关系与疑点，阻断依赖该材料的处理 | 素材/负责人核实选用或补料；可选脚本移出输入也须记录理由 |
| 保存/确认时版本已变化 | 拒绝旧版写入，保留待提交编辑和当前版本提示 | 对比后重新提交，不能后台自动合并或复用旧确认 |
| 改语言、市场、范围、路线、输出或执行策略 | 新建任务修订；原确认/授权是否覆盖重新判断，readiness重检 | 重新确认准确快照；旧Run仍指旧版，不自动改绑或重跑 |
| 换剪辑/主声音或母版 | 新Media及来源关系；新任务修订引用新母版，相关旧结果标需重验 | 重新核对确认；不回退编号/删历史，不取消外部发布当作本地回滚 |
| 无权确认/授权撤回 | 拒绝相应动作，保留权限检查；不更改确认字段或发起未授权调用 | 有权人处理或重新授权；实际权限等级配置待补 |
| 重复请求/响应丢失 | 按同项目请求防重返回既有结果；未知结果先查询，不重复确认或启动 | UI重试复用请求标识；新业务意图使用新请求，不靠重复点击新建多任务 |

读取、交料、修改任务、确认母版、确认任务、授予执行许可分别判断动作权限；不假定拥有其中一项便拥有其他项。对已COMPLETED/CANCELLED任务按主PRD另建关联任务，不重写历史。运行中修订只影响明确受影响范围及后续调用；在途处置、旧结果是否可采用由10/08细化，不能默认自动取消或自动接受。

## 7. 能力接口、数据链路与留痕

### 7.1 本功能的调用契约

以下名称描述业务能力，未冻结HTTP路由/协议/序列化；不声称已有接口。实际主体来自可信身份上下文，不接受浏览器自报管理员身份。

| 能力 | 请求内容及前置 | 成功返回/写入 | 失败语义 |
| --- | --- | --- | --- |
| 登记/查询素材 | 项目、受控文件和来源/授权、既有接收引用；读取/写入权 | Asset及实际可用性/检查结果 | 未授权、未收到、不可读分别说明，不伪造有效素材 |
| 核对/确认母版 | Media、选用Asset和检查引用、预期修订；有权人工确认 | Media确认结果及决定引用，02摘要可读 | MASTER_UNCONFIRMED、ASSET_MISMATCH或无权；不写虚假确认 |
| 保存/查询任务 | schema任务内容、`request_key`；修改附预期修订 | Task草稿/新快照、缺项；同项目同request_key返回首次创建结果 | TASK_INCOMPLETE；并发旧版拒绝，不能改既有快照 |
| 确认任务 | Task确切修订、母版及所需输入/输出；有权人工操作 | `confirm_task`决定、确认字段、`task.confirmed` | 缺项/版本过期/无权，保留草稿 |
| 检查就绪/申请执行 | Task修订、stage/所选模块、执行策略及授权引用 | readiness及依据；交接请求受理/拒绝，不直接返回“ASR完成” | STAGE_NOT_READY、失效许可、预算停止等，执行控制由10复查 |

确认写入应保证对象状态、决定和事件不出现“只写成功一半”的对外结果；具体事务/可靠投递由实施方案实现。相同Task创建`request_key`配不同业务内容时返回冲突并提示查询原任务，不静默吞掉新意图；具体冲突码待接口细化。浏览器重试不能导致重复业务动作；事件`dedup_key`不代替任务请求幂等。

### 7.2 输入到展示的链路

| 来源/动作 | 保留的数据 | 页面/后续用途 |
| --- | --- | --- |
| 真实交料和工程检查 | Asset原件/校验值/来源授权、inspection；Media.match_checks | 01素材清单、可用性和核对依据 |
| 人工确认母版 | Media确认字段；`ReviewDecision.action=confirm_master`；`media.confirmed` | 01确认摘要，02引用确切母版 |
| 编辑/确认任务 | 不可变task_revision、缺项/阶段要求；`confirm_task`决定及`task.confirmed` | 02摘要和明确交付范围 |
| 就绪/权限检查 | `readiness.checked`、实际权限事件及相关Validation/Run引用 | 02缺项/就绪、03开工依据；后续追踪不丢失败 |
| 实际模块执行 | 既有Run/attempt/step及input_refs/output_refs | 每步主体、输入输出、错误和版本可回查 |

先创建真实Task草稿，收料、抽轨/检查及母版确认均绑定同一Task ID；确认不换号。旧无Task原始收料历史不回填，不能作为新流程继续无任务抽轨/确认的依据，具体以schema§6为准。

先有Task草稿，工程素材准备使用`module=ingest`并保留Run/步骤及Asset.inspection/Media.match_checks；没有Task不新建抽轨或确认操作。步骤键(run_id,attempt_no,step_id)不另造新追踪体系；草稿期素材准备记录的持久化/查询接口须在实施方案验证。

指标引用`MET-INT-001`，按既有分母统计请求开工任务；重复检查不增任务分母。失败、缺项、人工等待真实记录；source-only、多语和单模块分层观察。本文不修改公式、不承诺提升值，未采集不补0。
