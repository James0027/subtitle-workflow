## 1. 两层分工

主PRD保存全局约定与导航，子PRD展开完整功能的行为和契约；通用subprd模板不构成中间管理层。数据字段、规则参数、指标公式各自引用03-foundation权威文件，不在两层PRD重复定义。

| 内容 | 主PRD负责 | 子PRD负责 |
| --- | --- | --- |
| 定位/业务目标/范围 | 简述全局与首批，引用BRD/metrics；质量、效率、治理目标和护栏 | 说明本功能贡献、适用范围及局部指标引用 |
| 角色、权限与预授权 | 职责边界、有/无授权、不可替代的人工节点和共同判定原则 | 本功能具体动作/对象、可操作条件、拒绝/请求授权反馈；不另造权限体系 |
| 系统架构 | 工作台、编排、六模块、共享上下文、适配、存取和控制如何协作 | 本功能调用哪些能力及必要依赖；不重新画一套全局架构 |
| 主链路/异常链路/状态 | Task整体状态、阶段准入/交接、全局阻断/恢复和局部修复原则 | 模块内步骤、具体失败码/数据异常、重试/兜底及动作后的状态；枚举引用schema |
| 全局文档导航 | BRD、原型、数据/规则/指标、子PRD和后续接口/测试的位置及内容摘要 | 引用本功能实际需要的章节，不整包重复上游 |
| 页面与接口调用全景 | 每页职责、操作触发哪类能力、前置顺序、结果影响哪些页面/阶段 | 请求/响应字段、业务语义、错误码、具体交互、输入校验和数据准备；完整接口契约只维护一处 |
| 系统数据全景 | 数据来自哪里、经过哪些处理、产生哪些对象/版本、回到哪里展示 | 本功能所读/新建/修订对象及字段的精确映射、事务和局部血缘 |
| 子PRD内容大纲 | 文件/功能/状态/BRD/内容速查；随实际子文档建立更新 | 对应功能正文、完整输入输出/工具/规则/兜底/验收 |
| 验收 | 全局验收、跨模块权限/状态、需求覆盖索引 | 本功能正常/异常/权限场景及具体预期；每条P0/P1至少三类，保留需求/场景ID |

## 3. 后续承接约定

10展开执行授权，08展开人工决定/版本，07展开包/签发，09提供共享上下文与规则；六处理模块按专业职责调用，共用schema与控制。跨功能场景只有一个主责，配合功能引用；不得各写一套权限/存储或每模块各建知识库。
