## 一、产品定位、范围与业务目标

### 1.1 产品是什么

面向字幕制作、翻译、审校和交付人员的协作系统。用户明确任务后，工程工具与模型生成候选、执行适用检查；人在关键节点确认，在异常处判断和修复。用户应能看清：本次处理什么、现在卡在哪里、下一步由谁做什么。

七业务阶段保持：**素材入库 → 听写对齐 → 初翻 → 文化审校 → 语言审校 → 格式质检 → 发布**。六处理模块是执行职责划分，不替代七阶段；单位格式模块可在翻译后、语言终审前按任务条件运行，V3与初翻合页展示不改变模块边界。发布指人工外部流程及回执记录，系统无自动发布权。

### 1.2 全局与首批

| 范围 | 约定终点 | 对应BRD |
| --- | --- | --- |
| 首批源语闭环 | 创建稳定ID任务草稿/素材准备 → 确认母版与任务 → 转写或核对/对齐 → 真人审核 → 内部生成/检查 → 真人签发 → 正式源语导出及记录 | F-01/02及F-07—10最小部分 |
| 后续全链路 | 接入翻译、文化、单位、语言审校及多语交付；生成合格包后有权人员签发并交接 | F-01—10 |
| 单模块调用 | 用户明确创建模块任务、提供合格输入，得到约定模块产物和记录；不代表全链已完成 | 复用对应F-02—07及F-08—10，分批提供 |

不承诺全语种/市场/平台同时覆盖，不自研ASR/翻译基座，不做自动配音或完整组织管理系统。数据/模型/工具/部署选型未定；当前只有设计、静态原型及空代码框架。

## 二、角色与全局权限

### 2.1 职责及可执行动作

| 职责/主体 | 主要动作 | 不可替代的边界 |
| --- | --- | --- |
| 素材提供/媒资职责 | 交料、补料，核对作品/集数/剪辑/音画和来源，确认母版 | 文件检查通过不自动等于母版正确 |
| 任务负责人 | 明确任务、范围、输入输出和接手责任，按权限授权/撤销、协调恢复 | 负责人身份不自动拥有所有审核/签发或跨项目权限 |
| 源字幕/翻译审阅职责 | 回听/对照、接受、编辑、驳回、补证、升级 | 只能处理授权对象和当前修订 |
| 高级本地/法律等裁决职责 | 处理证据/规则/高影响语义冲突，给理由及可执行处理 | 普通审阅不能代替该范围裁决 |
| 质检/签发职责 | 检查失败定位、最终审稿、核对文件及签发 | 必须同时具备对应内容及交付动作权限；同一人可兼任 |
| 工程工具/校验器 | 登记、可读性/格式/时间等确定性检查，版本、权限、幂等、记录及导出控制 | 不把技术PASS称为语义正确或人工已审 |
| 模型/运行模块 | 在任务及工具权限范围生成转写/译文/改写/风险候选 | 不覆盖已确认/锁定稿，不代签或自动发布 |

这是职责矩阵，不是已落地账号体系；具体人员等级和职责授予关系待补，未配置不默认真实用户有权。

### 2.2 授权与前置条件

默认按既定节点逐次复核。有权人员可以对指定任务修订、执行主体、模块和动作预授权；每次敏感动作仍检查权限、输入版本、有效规则、质量准入、预算和停止条件。

| 当前条件 | 系统动作 | 用户可做什么 |
| --- | --- | --- |
| 条件齐备、授权有效 | 执行范围内操作；中间候选可继续下一模块，继续保留AI_PROPOSED | 查看依据、进入审阅、调整要求或撤销后续自动授权 |
| 条件齐备、无授权/授权已撤销 | 不执行敏感动作；给等待/拒绝原因及授权入口 | 请求有权人员处理，或由有权人逐次确认 |
| 已授权、缺必需声音/源稿/上下文/规范 | 阻断受影响步骤，列缺项/责任/补料入口 | 补齐后重新检查，或明确修改任务范围并重新确认 |
| 已授权、检查失败/有待决阻断/触及停止条件 | 保留依据与产物，进入阻断/停止/人工等待 | 修复、裁决或按规则重新授权恢复 |
| 母版最终确认、最终审稿及签发 | 必须有权人员实际决定；预授权不等于已审过 | 有相应权限者确认；不能把机器运行记作人工决定 |

撤销授权后，执行端在后续敏感动作前重验，不再新发起未授权调用或写入。已发生调用不伪装撤回，返回结果受控保留且不推进后续；取消在途请求的工具能力另在子PRD核实。任务/输入变更后重新判断授权和就绪，不能无范围继承旧许可。

## 三、系统架构与原则

```text
任务与审阅工作台
  → 任务/权限/阶段条件检查 → 流程编排或单模块入口
  → 六处理模块：ASR对齐、翻译、文化、单位格式、口语审校、合规
  ↔ 共享上下文/规则（项目边界、版本、可用性）
  → 候选/问题/人工决定 → 指定版本检查 → 文件/签发/外部交接记录
  ↔ 全程Run/attempt/step、事件、费用和输入输出血缘
```

1. 复用模块能力：全流程与单模块使用同一输入输出契约，不为每个模块复制知识库、通用rules/skills或权限系统。
2. 代码负责确定性检查，模型负责语义候选，人负责必要裁决。模型未调用记录not_used，不能为了凑Agent虚构调用。
3. 每次执行固定上下文、规则及输入版本，更新不热改正在运行的快照。
4. 候选不可原位改写；人工确认稿受保护，任何修改另建版本，保存前复查修订和权限。
5. 无数据、未执行、失败、不适用分别展示，不用0分/空结果/成功百分比填补未知。
6. 用户决定标准和行为；具体工具、存储、接口路由和任务队列留实施方案。本文不指定技术栈。

### 3.1 组件职责

| 组件 | 负责什么 | 边界 |
| --- | --- | --- |
| 工作台与流程编排 | 收集任务/决定，按条件调度全流程或单模块 | 页面顺序不代替执行准入；不重写专业判断 |
| 六处理模块 | 按各自契约处理输入、产出候选/问题 | 不直接改其他模块结果或人工确认稿 |
| 模型/工具适配 | 调用供应商及媒体工具，返回结构化结果 | 不自行授予权限、确认内容或签发 |
| 共享上下文与控制 | 按项目/版本取规则与资料；校验权限、版本、幂等、预算及停止条件 | 全部入口共用控制，不各建权限/知识库 |
| 数据与文件存取 | 保存对象关系、修订、受控文件引用和历史 | 逻辑对象不等于数据库已建；文件存储不另管一套任务状态 |

现有目录已具备职责分离，具体路径见[AGENTS§3](../../AGENTS.md)。本轮不重构空框架；开发skills用于建设过程，不自动充当运行模块的业务规则。接口/队列/数据库选型留后续技术方案。

## 五、页面与接口调用全景

### 5.1 两种入口

| 入口 | 创建/确认内容 | 开工与结果 |
| --- | --- | --- |
| workflow | 作品/母版、source_only或multilingual、用途/语言/市场等适用条件、范围、输出、module_plan和责任 | 全局要求确认后逐阶段检查；只启动已批准且具备条件的阶段；未明确多语目标不自动改成源语任务 |
| module_only | 明确所选模块，提供或引用授权范围内的输入、必要上下文、语言/市场/规范及输出要求 | 无需重跑全部上游，但仍须合格输入、确切版本、授权与该模块准入；不适用字段显式说明，未知不当不适用 |

例如单独翻译仍需可用源稿和目标要求；已有外部源稿可先登记并核实，不要求它必须由本系统ASR生成。单独文化检测交出问题/证据及审核记录，检测任务完成不等于字幕可以发布。有未决风险时不能将诊断产物冒称合格字幕包。

| V3页面 | 主要操作 | 系统响应与联动 |
| --- | --- | --- |
| 01 素材/母版 | 登记、补料、核对并确认母版 | 留原件、检查/匹配及内容资料；02引用确认版本；换母版重新检查受影响任务 |
| 02 任务单 | 明确调用方式、路线、范围/输出/责任及复核方式，确认任务或授予/撤销许可 | 保存准确快照；列就绪/阻断/缺项；03只能执行对应版本和权限范围 |
| 03 ASR/对齐 | 查看处理、结果、疑点和失败，申请恢复或转人工 | 每步骤状态可查；默认交04，获准且符合条件可继续中间处理 |

| 05 初翻/单位候选 | 对照源文与上下文，处理术语/数值/日期建议 | 按目标分支另存候选及问题；改变内容使相关下游检查失效 |

| 08 检查交付 | 源语导出、多语质检、查看失败、最终审核及签发 | 文件绑定检查与修订；有权者可同页完成必要决定；无外部回执仍未知 |

页面可以浏览，不代表可以越过开工/审核条件。真实产品按权限和对象状态显示动作及不可操作原因，前端隐藏按钮不能代替服务端校验。接口能力需要创建/查询任务、发起/查询运行、获取候选/问题、提交决定、检查/生成产物和签发；具体协议/路由由子PRD明确，不假设已有API。

| 04—07审阅/批量/回滚 | 取当前稿与候选/证据→提交决定或修订→逐项权限/版本检查→保存 | 成功/冲突逐项反馈；受影响下游标待复检 | 08，相关业务模块 |

| 08最终审核/签发 | 核对内容决定→核对当前包/检查/未决项→再查签发权→留签发决定 | PUBLISH_READY；同页兼任仍保存两类实际决定 | 07、08、10 |
| 登记交接/回执 | 核对交接对象及权限→记录真实外部结果 | 成功回执才PUBLISHED；退回关联原包和修复任务 | 07 |
| 任一页查历史/追踪 | 校验项目及对象读取权→按受控引用取历史/执行链 | 当前稿、失败、费用、步骤和依据；不泄露跨项目资料 | 08、09、10 |

查询进度不能触发重新执行；写操作以服务端检查为准。异步处理先返回受理及可查询标识，再展示真实执行结果，不在点击后立即伪称完成。上游修订成功后刷新依赖关系与就绪状态；页面跳转本身不改变审核/签发状态。

### 6.1 阶段输入、产出及交接

| 阶段/模块 | 输入与开始条件 | 产物 | 交接条件及人工入口 |
| --- | --- | --- | --- |
| 素材入库 | 视频/声音和可选字幕/脚本等；素材与任务可交错准备 | 确认母版、任务快照、检查/缺项 | 母版和任务都确认，阶段必要条件齐备；提供补料/核对入口 |
| 听写对齐/asr_alignment | 指定母版、可用声音、源语言及范围；已有字幕按任务选择核对/对齐 | 文字/时间候选、差异、疑点和步骤记录 | 默认人工复核；获准有效准入后可将确切候选继续下游；源语直接导出仍须人工确认 |

| 单位格式/unit_format | 目标文本中的适用实体、原值、语境及有效策略 | 单位/日期候选及计算依据 | 按任务适用性在终审前完成；无适用实体可有理由SKIP，未知不是SKIP |
| 语言审校/oral_review | 指定目标稿、文化/单位处理结果、角色风格及阅读约束 | 可读性/语义问题、改写候选、人工终稿 | 最终审稿覆盖交付范围及源语依据；未审/阻断/缺权限/旧版不确认 |
| 格式质检/compliance | 人工确认稿、输出规格及适用有效规则 | 定位问题或字幕文件/检查与版本清单 | 实际技术检查及导出解析一致性通过才VALIDATED；诊断文件不算合格包 |

仅源语路线不经过目标翻译/文化/语言终审，直接“04人工确认→08源语检查导出”；多语路线依任务进入相应模块。模块判断以module_plan和有效规则为准，不因页面顺序固定重跑不需要的模块。

### 6.2 Task业务状态迁移

以下枚举与schema一致。Task显示整体工作情况，readiness单独表达各阶段就绪，不能用某次Run成功代替整个任务完成。

| 当前 → 下一状态 | 触发者与条件 | 持久结果/不满足时 |
| --- | --- | --- |
| DRAFT → NEEDS_INPUT | 确认/检查发现任务要求或必要材料不足 | 保存草稿与missing_items、责任和影响阶段；不启动依赖步骤 |
| DRAFT/NEEDS_INPUT → READY | 有权人确认当前任务快照，母版及待启阶段条件通过 | 留确认/就绪依据；不伪称尚未检查的全链都就绪 |
| READY → IN_PROGRESS | 对指定模块发起获准执行，运行实际开始 | 新建/引用Run及版本；重复请求复用有效结果 |
| IN_PROGRESS → WAITING_REVIEW | 到指定人工节点或出现需人判断的产物 | 留候选/问题/责任；自动路线符合条件时可继续IN_PROGRESS |
| READY/IN_PROGRESS/WAITING_REVIEW → BLOCKED | 必要授权/版本/输入/检查失效、硬阻断或执行停止 | 保留原因、已有产物和未执行步骤，不抹去失败 |
| BLOCKED → NEEDS_INPUT | 明确需要补料或重新定义任务 | 列缺项；更新任务另建快照，旧运行不自动改绑 |
| BLOCKED/WAITING_REVIEW → READY | 对应问题已解决且由有权者确认/授权，重新检查通过 | 仅恢复约定阶段；旧失败/费用/重试计数保留 |
| WAITING_REVIEW → IN_PROGRESS | 必要人工决定保存成功，仍有获准后续处理 | 创建对应复检/运行，旧输入变化先拒绝 |
| IN_PROGRESS/WAITING_REVIEW → COMPLETED | 本任务约定终点已达成，必需人工决定/检查/产物记录齐备 | 源语为内容真人确认、当前文件校验、真人签发及正式导出/交接记录；多语为签发及约定交接；单模块按自身产物/审核验收，不冒称全链完成 |
| 任一未结束状态 → CANCELLED | 有取消权限者明确取消并留理由 | 不再启动后续敏感动作；已发生费用和历史保留，在途结果不能继续推动取消任务 |
| COMPLETED/CANCELLED → 保留原状态 | 后续修改需求、返工或外部退回 | 另建关联任务/执行并引用原任务，不静默改历史快照；Artifact可继续登记真实回执 |

未设置承诺交付时间时，准时/SLA指标不可评价；COMPLETED不自动等于PUBLISHED。源语、多语、单模块的完成条件在任务确认时明确，不能事后移动终点来缩短TAT。

### 6.3 执行与产物状态的关系

| 层级 | 全局判定 | 详细契约及承接 |
| --- | --- | --- |
| Run及步骤状态 | 单步通过≠模块成功≠任务完成；等待、失败、停止和不适用分别保留，不把未知记PASS | 枚举/唯一键引用schema；10展开重试/恢复，六模块展开内部步骤 |
| 候选、人工修订、校验与交付状态 | 自动候选继续仍AI_PROPOSED；人工编辑草稿≠明确确认；修改另建修订，旧PASS不证明新稿 | 08展开决定/锁定/并发；07展开绑定确切版本的校验及文件 |
| Artifact | DRAFT→QC_FAILED或VALIDATED；有权人工签发后PUBLISH_READY，真实外部成功回执后PUBLISHED | VALIDATED仅为内部已验文件；源语也须真人签发后正式导出；导出失败不伪造成功；07展开 |

追踪最小链为Task→Run→attempt→step→输入/输出Ref。步骤实例键(run_id, attempt_no, step_id)，每步可查做了什么、执行主体、输入输出、真实状态/时间及失败依据。同配置重试保留run_id并增加attempt_no；改配置或人工重跑新建关联Run，不能重置Task累计费用与停止历史。

### 6.4 全局异常、人工干预与恢复

| 异常 | 系统反馈及阻断范围 | 接手动作及恢复条件 |
| --- | --- | --- |
| 视频不可读/无可用声音/错版 | 定位素材与检查；停相应ASR路线，其他不依赖工作可继续 | 素材方补料，媒资核对；新素材留来源/版本，重新检查 |
| 缺脚本/字幕/内容资料 | 列缺项及影响阶段，不一律阻断ASR；专名/语境无依据明确待定 | 负责人补充或安排人工核实，不能捏造角色和证据 |
| 缺授权/撤销/跨项目访问 | 拒绝对应动作、记录permission.checked及实际未写入 | 请求有权人处理；不能通过隐藏按钮或换主体绕过 |
| 低置信/未校准/缺上下文 | 不启用无依据自动档；留当前可用产物及必审/补证入口 | 人回听/手译/补资料；不以模型自评分替代校准，不同配置重跑留版本 |
| 规则冲突/文化证据不足 | 展示双方适用范围、有效期、触发片段及证据状态 | 有权本地/高级/法律责任人裁决；未决范围不可签发，无证据不伪称确定P0 |
| 并发/输入过期 | 保存前expected_revision或输入引用不符即拒绝该项 | 保留待提交内容、旧候选和失败，重新对比当前稿再决定 |
| 服务失败/空输出/输出结构非法 | 显示真实错误及已发生步骤，下游未执行；空结果不作成功 | 工程排障或任务负责人转人工；重试服从资格、预算及总停止条件 |
| 预算/连续重试达到停止条件 | 停止新调用，保留成本及尝试；无配置不启动付费路线 | 负责人核实原因并按权限批准恢复；不得新建run来逃避Task累计控制 |
| 驳回/升级/关键语义改变 | 原稿与候选保留；驳回不自动生成正确稿；阻断项不能批量略过 | 编辑后确认、补证或升级；省略片段须有明确有权决定，不擅自漏导 |
| 回滚/上游修订/规则变更 | 找出依赖该版本的候选、问题、检查和文件；标明待复检 | 人确认或在明确授权内局部重跑；无关范围不重跑，有关范围重新审核/检查 |
| 技术检查失败/外部退回 | 显示片段/行、文件版本、规则和回执原因；不能称合格交付 | 回相应模块修复后重新走受影响验证；外部已发布动作不能当成本地回滚自动撤回 |

追踪示例：发现某目标句丢失“不”→由segment/目标分支/修订定位candidate及Run/attempt/step→回查当时源稿、模型/Prompt/术语/规则→确定是源语、翻译还是改写问题→生成修复候选并人工确认→只重验依赖该内容的后续结果→重新生成对应包。若回滚，另建修订，旧决定和事故结局保留。

各模块特有的错误码、分段策略、超时/退避、模型准入和工具兜底由对应子PRD展开；未确认参数不在主PRD补造。四条底线RULE-SUB-001—004统一适用：保护人工稿、不绕过签发、外部规则可追、预算/重试达停止条件即停。

### 7.2 版本影响与可追踪边界

| 变化 | 重新判断什么 | 保留什么 |
| --- | --- | --- |
| 换母版、输入或任务范围 | 受影响阶段readiness、授权范围及输入引用 | 原件/原任务快照、原运行和实际费用 |

| 撤销授权或外部退回 | 后续敏感动作是否获准；包及修复任务如何关联 | 已发生调用/交接和真实回执，不伪称外部动作已撤回 |

manifest记录实际输入、上下文、规则、模型/Prompt/工具的版本引用；未调用模型标not_used。用户不必填写内部trace/step编号；界面默认展示任务/版本/状态/问题及操作，技术明细按需展开。素材正文、音视频使用受控引用，不无差别复制进日志；权限、敏感信息及留存按项目规范处理，具体保留时长待技术/授权方案确定。
