## 1. 范围与需求

识别目标稿中温度、距离/速度、货币、日期/时间等实体，结合源语剧情和目标地区策略提出表达或换算候选。本文“格式”指数字与日期等本地表达；SRT/TTML结构、编码、glyph和交付文件质检归07。

首批源语闭环不承诺本模块上线。后续可按module_plan在翻译后、语言终审前执行；单模块任务须已确认任务、合格稿及对应源语依据、目标范围和有效策略，不要求全链重跑。

| 局部需求 | 优先级 | 上游需求 | 本文负责 |
| --- | --- | --- | --- |
| REQ-UNIT-01 | P1 | REQ-MAIN-R09 | 定位实体及语境，区分保留、本地表达和可换算 |
| REQ-UNIT-02 | P0 | REQ-MAIN-R09 | 确定性计算、精度/舍入与原值全程可查 |
| REQ-UNIT-03 | P0 | REQ-MAIN-R09 | 日期、汇率及剧情例外不推断、不静默替换 |
| REQ-UNIT-04 | P1 | REQ-MAIN-R09 | 对比、采纳/驳回与局部交接，不覆盖确认稿 |
| REQ-UNIT-05 | P0 | REQ-MAIN-R09 | 固定版本、权限/停止与实体级指标可追踪 |

共享人工采纳归08；策略获取/有效性归09；执行/授权/预算归10。本模块不能用“工程换算”代替语境和权限判断。

## 3. 识别、判断与计算步骤

1. 核对确认任务、确切稿/源语依据、目标地区及处理范围。默认读人工修订；中间候选须有效预授权和准入通过，引用确切AI_PROPOSED候选。
2. 识别实体及出现位置，关联源语原值、单位与语境；温度数字、日期、密码或纪录均先识别，不把“不应换算”当实体漏检或不存在。
3. 请求09提供适用、有效、版本明确的conversion_policy，区分仅本地表达、允许换算、明确保留和需人工核实。未知策略不是不适用，不自动按市场猜原日期或数字含义。
4. 对获准确定实体，由代码按已选公式和精度/舍入计算；保留中间因子及原始精度。模型可辅助识别和解释，不作为数值计算权威，不让模型自选汇率或日历。
5. 检查单位维度、原值/结果对应、换算反查及舍入依据。无公式版本、精度或结果非法时不出合格替换；涉及发烧、烹饪、实验等语义敏感表达先人工核实。
6. 保存保留/替换候选及例外说明。原值在证据和版本中保留；剧情要求屏幕继续保留原值时不能仅后台留档后删掉可见原值。
7. 默认交译审逐条决定；有效许可可把检查通过的机器候选交后续中间处理，仍AI_PROPOSED，最终人工审稿不可省略。内容被采用后06/07按新修订复检受影响项。

明确无适用实体且检查实际完成时可有理由SKIP；识别失败、策略未知或未执行不能写SKIP/PASS。是否“无实体”须覆盖所选范围，不以空输出替代检查。

## 4. 剧情例外与局部规则

| 情况 | 允许动作 | 禁止动作/去向 |
| --- | --- | --- |
| 日常温度/距离/速度 | 适用策略明确后给可解释候选 | 不套课堂有效数字或整数精度作生产默认 |
| 密码、比赛纪录、科学数值、关键剧情原值 | 保留原值及例外理由，必要时附获准说明 | 不为本地习惯直接改数字；语境不清交译审 |
| 剧情金额 | 可按有效策略调整符号/分隔符等展示，保留原货币含义 | 不按实时汇率变更金额，不把币种改成目标市场货币 |
| 获准购买信息换汇 | 校验用途许可、汇率来源/日期/基准币种与快照 | 缺任一依据不换汇，不用当前网页估算 |
| 03/04等歧义日期 | 请求确认原义；明确后可展开月份 | 不靠目标市场决定源日期，不推断历史日期/时区/日历 |
| 颜色、数字、手势文化线索 | 保留提示并交04文化审校 | 不将风险提示直接变为数值替换或文化裁决 |

## 5. 页面动作与反馈

对应[05初翻与本地化候选](../02-prototype/pages/05-translation.html)的单位/日期区域；翻译区域归03，文件质检入口归07。

| 动作 | 页面反馈 | 写入边界 |
| --- | --- | --- |
| 查看实体/依据 | 源句、原值/单位、目标建议及类型；展开公式、精度、舍入和策略版本 | 原值始终可回查；缺依据显示待补 |
| 发起检查/局部重算 | 处理中与实际覆盖；新候选保存成功后显示 | 10复核范围、许可与预算，不重复触发付费动作 |
| 接受/编辑后接受/驳回 | 08返回新修订/保留原值及原因 | 编辑仅草稿，明确接受另记；锁定稿不原位改 |
| 请求确认日期/剧情例外 | 显示缺义、受影响位置和接手职责 | 未确认不改稿，不将“已查看”算解决 |
| 批量处理/交接 | 逐条展示成功、被阻断、旧版和无权项 | 不对需剧情判断项静默批量确认，不全批假成功 |

失败保留未提交编辑及旧候选；并发变化显示对比并拒绝旧版写入。无权按钮说明原因，服务端仍独立验证。

## 2026-10-22 两段式白盒换算与AI状态机规格补充

依据课件§4.5、§5.3及导师指导纪要（确定性工程换算、无实体跳步、剧情例外硬锁），确立以下实施规格：

### 1. 两段式白盒流水线架构
- **第一段：纯工程实体抽取与跳步机制**：
  - 通过正则/ICU库扫描译文；若全句无任何数值/单位实体，**整步直接跳过 (SKIP)**，零Token消耗、零延迟。
  - 存在标准通用物理单位（如公里/米/千克）时，由Python底层工程代码依目标市场策略执行确定性计算与舍入，必须通过数学反向验算：$|\text{target\_value} \times \text{factor}^{-1} - \text{raw\_value}| < 0.01$。
- **第二段：AI语境与例外分类器（只判语境，不作算术）**：
  - 仅在命中温度（发烧 vs 气温）、货币金额、比赛纪录、数字密码等敏感场景时介入。
  - AI提示词仅作单项分类选择，判定是否属于“剧情关键线索 (Plot Exception)”。
  - 触发剧情例外时，机器**强制剥夺自动替换权**，置为 `MANUAL_DECISION_REQUIRED`，页面并排高亮原值与换算值供审校裁定。

### 2. 剧情线索防篡改硬约束
- **剧情金额禁止套汇率**：严禁按现实汇率折算剧情货币（如100美元算成比索），货币仅做符号与千分位规范化。
- **原值零丢失原则**：原文数值与单位永久写入 `evidence`，换算仅作为“建议替换”，界面并排展示 `[建议值 (原值: xxx)]`。

### 3. 全局AI来源标识与四态流转契约
AI来源永久可见，人工确认或编辑不抹除AI生成血缘：
- `AI_PROPOSED`：⚡ [AI建议]（机器建议替换，待人工裁定）
- `HUMAN_APPROVED`：⚡ [AI生成 · 人工已确认]（人工采纳机器换算，记录版本血缘）
- `MANUAL_EDITED`：✎ [人工修改 · 基于AI候选]（人工介入修改数值，记录操作人与diff）
- `ORIGINAL_RETAINED`：🛡️ [人工锁定 · 保留源单位]（确认原值为剧情线索，锁定原值）
| 结果溢出、非法数值或工具失败 | 记录真实失败及输入，不装计算成功 | 工程修复/人工核算；10管理可重试条件 |
| 输入改版/策略更新 | 旧候选保留，受影响结果需复检 | 08处理新修订；不将旧PASS或决定套新稿 |
| 超预算/授权撤销/写确认稿 | 停止或拒绝，已有产物保留 | 10有权恢复；不能靠“只是格式化”绕过权限 |

确定性工具负责计算和地区展示；模型仅在需要时帮助识别/解释；译审判断剧情原值与歧义，规则负责人批准策略。无需模型时manifest标not_used，不为凑六Agent流程虚构模型调用，也不在本轮选库/装依赖。
