## 1. 项目背景

### 1.1 业务现状

参考材料中的字幕生产链路为：素材入库 → 听写对齐 → 初翻 → 文化审校 → 语言审校 → 格式质检 → 发布。

各阶段由不同人员及 ASR、TMS、工程脚本等工具协作完成。实际输入可能包含视频、独立音轨、已有字幕和脚本，也可能缺少部分配套资料。不能统一假定所有任务都从零转写，或将现状描述为完全人工。

### 1.2 问题与痛点

重点验证以下问题：

- 源字幕错误可能传播到翻译与审校环节，造成下游返工。
- 人物、术语和剧情上下文需要跨环节共享，否则容易重复查找或产生不一致。
- 文化风险建议需要明确市场、上下文和依据，才能支持人工判断。
- 平台格式差异、版本混乱和修改难追溯，可能增加交付成本。
- AI 生成节省的时间，可能被新增复核和返工抵消。

这些来自参考材料和项目分析，实际发生频率、耗时和影响尚待验证，不作为已核实的企业现状或个人成果。

### 1.3 为什么开展这个项目

结合现有识别、翻译和规则校验能力，验证能否通过模块协作、共享上下文及人工审核，改善字幕质量和处理效率，并保留可追溯的决策记录。

## 2. 项目目标与成功标准

### 2.1 项目目标

帮助字幕处理人员完成从源语字幕到多语种交付的处理与审核，在守住质量和人工决策边界的前提下，减少重复操作及返工。

- 质量守底：内容、时间轴和交付规范满足约定要求。
- 效率增益：减少包含复核、修改和返工在内的净人工投入。
- 过程可追溯：能查明输入、处理依据、输出版本和人工决定。

### 2.2 衡量指标

| 指标 | 基本口径 | 基线值 | 目标值 | 统计周期 |
| --- | --- | --- | --- | --- |
| 内容质量 | 按模块统计转写错误、关键语义错误及漏检；使用适合语种的评价方式 | 待采集 | 评价标准与样本确定后制定 | 首轮按固定样本批次 |
| 时间轴质量 | 对照人工参考，分别统计起点和终点绝对偏差 P95；缺失事件另报 | 待采集 | 待制定 | 首轮按固定样本批次 |
| 净人工分钟/成片分钟 | 编辑、复核、修改和返工的有效人工时间 ÷ 成片分钟 | 待采集 | 对照基线后制定 | 按可比任务批次 |
| 任务周转时间 | 素材就绪至约定交付状态，单列外部等待；报告 P50/P90 | 待采集 | 待制定 | 按完成任务批次 |
| 技术质检通过率 | 按指定规范检查通过的交付版本 ÷ 被检查版本；首轮与最终分别报告 | 待采集 | 规范确定后制定 | 按交付批次 |
| 可追溯覆盖率 | 必要输入、版本、执行及人工决定记录完整的产物 ÷ 应记录产物 | 待采集 | 必要记录不得缺失，清单后续确定 | 按交付批次 |

首轮以固定样本和任务批次观察，不填虚构基线。自动放行或正式质量验收前，必须明确适用语种、样本、标准与目标；课件示例数值不直接采用。

### 2.3 统计口径：先定分母，再谈提升

依据课件 §3.4 补充以下口径，具体埋点字段、权重和数据实现留到指标锁定阶段，不因此宣称已有统计系统。

| 指标 | 分子与分母 | 聚合与注意事项 |
| --- | --- | --- |
| 建议接受率 | 未编辑直接接受且未撤销的建议数 ÷ 实际展示的建议数 | 按模块分开，先按审校人×语言计算；汇总权重后续锁定，同时报告样本量。批量操作拆回单条建议；修改后接受不算直接接受，撤销视为未接受 |
| 有效接受率 | 展示后获得接受、且接受后7日内未撤销或引发经确认下游错误的建议数 ÷ 同一展示批次建议数 | 按模块分层；包括直接接受和修改后接受，另报两类贡献。只有窗口完整且结果可核查的批次出正式值；未满7日或缺结果标记待观察，不能当作成功 |
| 人工编辑率 | AI 候选被人工修改文本的已审字幕事件数 ÷ 同批已审且有 AI 候选的字幕事件数 | 标点与实质修改分开，按编辑距离分桶；纯时间轴调整单列。人工从零补写、无候选情况单列，不能混入候选编辑率 |
| 漏检率 | 金标错误中未被 AI 标记且人工最终未修正的错误数 ÷ 同范围全部金标错误数 | 此处衡量最终流程共同漏检，P0/P1 分开；若评价 AI 单独漏检另定义指标。以错误项为单位，分母不是全部正常字幕；缺金标不能声称低漏检 |
| 误报负担（驳回提示负担） | 最终被驳回的提示数 ÷ 对应成片分钟 | 按模块和类别统计，并按任务报告 P50/P90。驳回可能因重复、建议无用等，不自动等于事实误报；另记驳回原因，不当作精确率使用 |
| 净节省 | 基线完整人工分钟 − 试点完整人工分钟 | 试点完整人工时间包含新增复核、修正和返工。若分项记录，则为基线 − 试点非新增复核人工 − 新增复核；两种算法择一，禁止重复扣复核。按可比作品/任务配对，模型纯等待不计活跃人工 |

**统一统计约束：**

1. **统计单位明确。** 字幕事件、建议、错误项、任务和交付版本分别计数，不互相代替。同一事件可包含多个错误或多条建议，保留对应关系。
2. **展示与去重明确。** 未展示建议不进展示分母；同一建议版本因刷新、重新打开而展示多次只计一次。不同候选版本分别留痕；重跑不能删除失败记录或通过重复生成抬高接受量，同输入重跑另报。
3. **分层可比。** 至少按处理模块、源/目标语言及任务类型区分；市场、平台、题材等按样本条件补充。不同分母的指标不直接平均；加权方式和权重确定后固定。
4. **人工与等待分开。** 记录有效人工操作，排除无操作空闲；空闲识别阈值在指标锁定时确定。模型纯等待、排队和外部素材等待分别记录；周转时间包含处理及队列等待，外部等待单列。
5. **质量约束先行。** 在同等约定质量和相近任务条件下比较效率；质量不达标的试点不得仅凭更快宣称提效。任务失败、放弃和未完成数量单列，不能静默从结果中删除。
6. **分母为零不填0%。** 报“不适用”并说明原因。无金标、无合格对照或样本不足时，只报告观察，不宣称收益成立。
7. **变化表述明确。** 百分比指标优先报告百分点；报告相对变化时给出计算式、基线和样本。时间/成本降幅为（基线−试点）÷基线，不与百分点混用。
8. **统计可回查。** 保留样本批次、输入修订、模型/提示词/规则版本和人工决定。报表说明窗口、样本量、未观察完数量及缺失数据；不能将尚未发现错误等同于已证明无错。

上述细化属于本项目对课件口径的落地说明。课件“净节省”公式中的试点人工是否包含新增复核必须区分，本项目统一采用包含全部复核的完整人工时间以避免重复扣减。

## 3. 目标用户与核心场景

### 3.1 利益相关角色

| 角色职责 | 核心诉求 |
| --- | --- |
| 源字幕处理人员 | 快速获得可回听、修订和确认的源语字幕 |
| 翻译人员 | 获得可靠源文、上下文和一致术语，检查初翻候选 |
| 文化与语言审校人员 | 基于证据判断风险，处理语言和剧情表达问题 |
| 质检与交付人员 | 定位技术问题，复检并生成合规交付文件 |
| 任务协调人员 | 明确处理进度、阻塞和交接结果 |

这是职责划分，不决定账号或后台数量；一人可以承担多项职责。具体人员配置与现有系统操作方式待核实。

### 3.2 核心场景

| 场景 | 预期支持 |
| --- | --- |
| 没有可用源字幕 | 从可用声音生成文字和时间轴候选，供人工检查 |
| 已有字幕 | 根据任务进行核对或对齐，保留原文件 |
| 制作目标语版本 | 基于明确源语版本、术语和上下文生成翻译候选 |
| 审查文化、单位及语言问题 | 定位问题，展示依据和建议，允许接受、修改、驳回或升级 |
| 修改后重新处理 | 保留人工确认稿，识别新旧版本，生成可比较的新候选 |
| 准备交付 | 按平台规范检查，内部生成文件和检查结果，经人工审核及签发后正式导出交付 |

## 4. 项目范围

### 4.1 In Scope：全局范围

以下功能编号作为后续原型、PRD、任务和测试的范围依据；细化不等于自动扩大范围。

| 编号 | 功能 | 范围说明 |
| --- | --- | --- |
| F-01 | 素材接收与检查 | 接收视频及配套文件，检查可用性并明确对应关系 |
| F-02 | ASR 与时间轴对齐 | 生成或核对源语字幕候选，支持检查和修订 |
| F-03 | 初翻候选 | 根据源字幕、术语和上下文生成目标语候选 |
| F-04 | 文化风险检测 | 提供目标市场风险线索、依据和处理建议 |
| F-05 | 单位与格式本地化 | 提供适用的单位、日期等表达调整建议 |
| F-06 | 口语审校 | 检查自然度、语气、断句和阅读负担 |
| F-07 | 合规输出 | 按选定规范检查并生成交付文件 |
| F-08 | 人工审核与版本保护 | 支持修订、接受、驳回及必要升级，保护确认稿 |
| F-09 | 共享上下文与规则 | 管理项目术语、角色资料及适用规则版本 |
| F-10 | 状态与执行记录 | 展示任务状态、失败及必要处理和决策记录 |

### 4.2 分批交付

全局覆盖六模块，分批实现和验证。

首个可验收版本：素材包提交 → 可用性检查 → ASR/对齐 → 回听与修订 → 真人确认源字幕 → 内部生成/检查 → 真人签发 → 正式导出与记录。

首批覆盖 F-01、F-02，以及满足该链路所需的 F-07—F-10 最小部分；不因此承诺完整多语种导出、规则管理后台或全部审核角色。同步具备人工稿保护、失败可见和必要版本记录。

后续逐批接入初翻、文化、单位、口语审校及多语种交付。语种、市场、平台、素材限制与具体批次计划在对应步骤确认，不假定全部自动适用。

2026-10-20交互边界补充：最终覆盖全链路，工程/模型能力尽量自动处理，每模块保留人工查看、调整和介入入口。有权人员可对具备有效准入条件的中间环节预授权自动继续；母版最终确认、最终审稿及交付签发保留人工责任。用户也可在已明确任务和输入条件下单独调用所需模块，复用F-02—F-07与F-09/10，不要求重跑全链路；这是全局设计能力，分批落地，不扩大首批交付承诺。具体人员权限等级与接口形式留主/子PRD，当前无后台实现。

### 4.3 Out of Scope：本期不做或暂缓

| 内容 | 不做或暂缓理由 |
| --- | --- |
| 自动发布到内容平台 | 保留人工签发和外部发布流程 |
| 自研 ASR、翻译基座模型 | 优先验证现有能力与业务价值 |

| 完整媒资、TMS 或组织管理系统 | 优先复用已有能力 |
| 提前建设向量库或复杂多模型路由 | 等实际需求与验证结果支持后考虑 |

## 5. 关键假设与风险

| 假设或风险 | 影响 | 应对方式 |
| --- | --- | --- |
| 样本及配套资料不完整 | 无法可靠评价效果 | 记录来源、缺失及派生过程，补人工参考 |
| 真实瓶颈尚未确定 | 可能优化低价值环节 | 记录操作、人工时间及返工，允许调整顺序 |
| 模型遗漏、误写或无依据补充 | 影响内容准确性 | 候选态、回听、人工确认及失败暴露 |
| 市场或平台规则缺失、过期 | 建议或标准不适用 | 明确范围和版本，缺失时提示与升级 |
| 重跑或并发覆盖人工稿 | 丢失已确认工作 | 修订校验、写入保护、新候选保存 |
| 外部服务失败或费用失控 | 中断或成本增加 | 失败可见、保留产物、预算与重试停止原则；数值及口径待定 |
| AI 增加复核负担 | 总体效率下降 | 统计完整人工投入，不只比较生成耗时 |
| 素材及凭据使用越权 | 泄露或未经授权调用 | 按授权读取和上传，凭据不进日志与源码 |

本文件确认业务方向和范围，不代表功能、统计、运行控制已实现，也不构成依赖安装、收费调用或部署授权。
